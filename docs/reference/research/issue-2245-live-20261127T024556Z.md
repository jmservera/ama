## Source change

`ChatPanel._ask.finish` in `src/core/src/zava_forward/core/chat_panel.py` now repeats the assistant-message save up to two more times when it fails with the SQL write-lock timeout. That save is one transaction that takes the lock first, so a timeout writes nothing and repeating it cannot duplicate a record or a model call. A persistent timeout still raises, so no unsaved answer is shown. Audit writes and the thread-creation path are unchanged. A regression test in `src/core/tests/test_chat_panel.py` fails without the change (verified by restoring the old file) and passes with it; the 208 `test_chat*` tests pass.

The fix is not deployed (live changes were outside the goal), so the live 500 after the fix is unproven.
