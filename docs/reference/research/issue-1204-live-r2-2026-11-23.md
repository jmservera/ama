Refs #1204. Synthetic demo, desktop only. Tier FOCUSED: `tools/` change only, no `src/` change, no Azure change.

## Gap and change

* The checker enforced the batch cap and repeats but not the instruction that a tick makes bounded closure-review progress when capacity is free. `tools/check-tick-log.py` now flags `closure-progress` for a row that carries `closure_batch`, has unassessed items, runs fewer than 8 sessions and reviewed none. Legacy rows without the key are exempt.
* `load_sqlite` now reads `closure_batch`, `approvals_granted`, `approvals_expired`, `reclassified` and `global_stop` when the session `tick_log` table has them, so a real window recorded under the extended schema is checked for every rule.

## Evidence

* `python3 -m unittest test_check_tick_log` in `tools/`: 13 tests, OK (2 new).
* `ruff check` and `ruff format --isolated --line-length 100 --check`: clean.
* Scan of every local session database: the one with a `tick_log` table (216 ticks) gives 0 violations, so legacy databases are unaffected.
