Refs #2243. Synthetic demo, desktop only.

## Finding

`expires_at()` falls back to the closed default `EXPIRES` (2026-11-01) when `ZF_DEMO_EXPIRES_AT` is unset, not UTC or unparsable. That date is past, so the chat shows "AI unavailable: the AI exercise has ended" for a configuration fault, the symptom first reported in #2243.

## Change

* `assistant.py`: `expiry_configured()` reports whether the setting parses as explicit UTC.
* `aoai.py`: past-expiry checks in `answer` and `answer_question` raise `expiry_not_set` when it does not; a valid past date still reports "ended". Both still fail closed.
* `tests/test_resident_aoai.py`: `test_missing_expiry_setting_is_named_not_reported_as_ended`.

## Live evidence (2026-11-23)

`az containerapp show -g ama -n ca-resident-demo` reports `ZF_DEMO_EXPIRES_AT=2028-01-01T00:00:00Z` on the active revision `ca-resident-demo--0000028`. The deployed setting is valid, so this change does not alter the live demo today; it makes a future misconfiguration diagnosable. No resource was created or changed.

## Validation

`test_resident_aoai` and `test_resident_demo_api`: 72 OK; `python3 -m mypy` clean; ruff check and format clean. Hosted CI not observed (not pushed).
