Scope: synthetic demo, FOCUSED tier. No live Azure (the issue forbids it), no `rpi-checks.py --all`, no change to `rpi-checks.py`. Builds on [r8](issue-1830-live-r8-2026-11-23.md).

## Gap and fix

Criterion 1 asks for queue wait. `tools/rpi-gate-timing.py report --log` read the `Lock queued ...; acquired ...;` line only when it matched, so a log without it silently dropped `queue_wait_seconds`. A malformed timestamp raised a traceback and a negative wait was reported as a number.

Now a log with no lock line reports `queue_wait_seconds: null` and `queue_wait_unavailable`; a malformed or reversed lock line is refused with exit 2. Two tests in `tools/test_rpi_gate_timing.py` cover both. The valid path is unchanged.
