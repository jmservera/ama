Scope: synthetic demo, desktop only, resource group `ama`, owner decisions of 2026-11-18. Azure use was read-only plus authenticated GETs from Playwright; no deployment, no throwaway resource. Sign-in values were read at run time and never printed. Refs #2320.

## Profile finding (criterion 1)

* `Store.briefing` reuses a cached result only if `release_current` accepts its release. A template briefing held by a release denial carries `release=None`, so with AI configured it never hits the cache and every GET runs the full path.
* On SqlStore that path takes the SQL write lock three times: the `ai_release_denied` audit in `release_block`, the comparison record save in `add_record`, and the `ai_run` audit. Each wait is up to 15 s (`mssqlstore.BEGIN`, `@LockTimeout = 15000`), which fits the 17 to 43 s 503s.
* Live container log, 2026-11-24 09:26 to 09:30 UTC, revision `ca-cutover-test-demo-api--0000060`: 503 `sql-write-lock-busy` for GET `/api/briefing`, `/api/retention` and `/api/assistants/simulation/quality`, and a 503 on sensors and on POST `/api/chat/threads`. Contention is system-wide (other demo traffic); briefing adds writes on a read.
* The `/api/assistants/forecast` confounder (#2304) was not re-measured.

## Fix

* `release_denial` (new, read-only) on `Store` and `SqlStore`; `release_block` audits through it as before.
* `_briefing_denial_unchanged`: a cached template held by a denial is reused while `release_denial("briefing")` returns the identical reason. A recorded release changes the reason, so the AI path resumes.
* Test `test_denied_briefing_recovers_after_recording_release_without_case_edit` now asserts the repeat GET returns the cached object, issues no `BEGIN IMMEDIATE` and appends no audit entry. It fails on the base (the cached object is replaced and a record and audits are written) and passes with the fix.

Validation: 682 tests OK (172 skipped) across `test_assistant_release`, `test_ai_tasks`, `test_error_logging`, `dataset`, `test_sqlstore`, `test_mssql_startup_lock` and `test_resident_decisions`; `ruff check` clean; `mypy` in `src/core` reports the same 3 errors as the base (OpenTelemetry stubs, one unused ignore). Tier FULL applies because `src` changed; the complete gate is the coordinator's and was not run.
