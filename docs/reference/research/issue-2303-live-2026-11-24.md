## Findings

* The report endpoint answers but slowly: 66 to 120 s in the API probe and 169 s in the UI. The screen shows "Loading recorded evidence." for that whole time and a user may give up. The container log tail at 12:32 to 12:39 UTC also shows `sql-write-lock-busy` 503s on other routes (`/api/assistants/forecast`, `/api/chat/threads`, sensors) and `read-doc` 500s, so the demo is under heavy SQL write-lock contention from other sessions. This is outside the #2303 criteria; it is noted for the owner and not changed here. `/api/cases/{id}` stays fast (2.5 to 3.2 s), so the delay is in the report path, probably the chat and cohort evaluation.
* A first probe used `wait_for_function` with a string, which the app's Content Security Policy blocks (`unsafe-eval`); it is a probe fault, not an app fault, and the final script polls `inner_text` instead.
