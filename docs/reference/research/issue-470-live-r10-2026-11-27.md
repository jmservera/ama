## Critical chain (g2182b, from `rpi-gate-timing.py report`)

Chain length equals the wall time, 3114.1 s. Dominant links: project-api unittest 1176.2 s, mssql 732.5 s, infra 482.9 s, project-agents 227.6 s, image-api 159.5 s, then image-importer 63.1 s; the setup links before them total about 190 s. In the same receipt project-core ran 1894 s in parallel and gated `browser`, which started at 1898 s; `mssql` followed `browser` serially from 2143 s to 2892 s, and the image builds ran last (2892 to 3114 s), so mssql and the images sit wholly on the tail after the 1.6 ks test phase. Concurrency histogram: 1 command running for 964.8 s, 2 for 1146.1 s, 3 for 192.7 s, 4 for 808.9 s.

In g2182 the `project-api` unittest hit its 1800 s timeout (exit 124) after about 3470 s of group span; `browser` and `mssql` never ran, so the 4333.5 s is a truncated, failed run and not a full-gate time.

## Comparison limits

* `tools/rpi-gate-timing.py report` refuses g2182: only passed schema 4 full-scope receipts are analysed. `compare --before g2182 --after g2182b` is refused for the same reason.
* The pair differs in head, base, tree (`2f0fcb06` against `e764c371`), jobs (1 against 2) and outcome, so it is not a controlled before and after.
* The issue baseline (23 to 26 min command time on 2026-10-27, serial) is a sum of command time from 17 runs that are not retained; g2182b has 7070.4 s summed command time and a 3114.1 s wall at jobs 2, so the suite is larger and the current wall time is above that baseline.
