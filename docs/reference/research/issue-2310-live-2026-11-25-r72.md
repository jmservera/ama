## Scope

Synthetic demo, desktop only. Read-only probes of `ca-cutover-test-demo-api` (resource group `ama`), latest and only active revision `ca-cutover-test-demo-api--0000072`, 100 percent traffic. No credentials were used or printed; no Azure change was made.

## Evidence

Local tests (worktree `src/api`): `python3 -m unittest tests.test_auth -q` ran 45 tests, OK. The relevant tests are `test_anonymous_api_is_401_for_browser_style_requests_and_pages_still_redirect`, `test_anonymous_api_never_redirects_for_any_method_accept_or_unknown_path` and `test_anonymous_api_put_patch_delete_return_401_not_501`.

Live anonymous probes (curl, no cookies):

| Request | Result |
| --- | --- |
| `/api/me` with a browser User-Agent and `Accept: application/json` | 302 to `login.microsoftonline.com` |
| `/api/cases` with the same headers | 302 to `login.microsoftonline.com` |
| `/app` with the same headers | 302 to `login.microsoftonline.com` |
| `/api/me` with `Accept: application/json` only | 401 with `WWW-Authenticate: Bearer` |
| `/api/me` with User-Agent `curl/8` | 401 |

Cause: `az containerapp auth show` reports `unauthenticatedClientAction: RedirectToLoginPage` with `excludedPaths` of `/healthz`, `/readyz`, `/`, `/welcome.html`, `/style.css`, `/zava-logo.png`, `/sign-in`. The platform layer intercepts browser-style anonymous API calls before the application sees them, so the application's 401 code path is not reached.

## Acceptance criteria

| Criterion | Status | Basis |
| --- | --- | --- |
| Anonymous protected API GET with browser User-Agent and `Accept: application/json` returns 401, not a redirect | Code proven; live revision 0000072 not proven | Application tests pass (45 OK). Live returns 302 because of the platform setting above. |
| Anonymous protected page request still redirects to Entra | Proven | Application test (302 to `/sign-in`) and live `/app` 302 to Entra. |
| Existing auth tests pass; no weakening of route protection | Proven locally | 45 `test_auth` tests pass; no source change. Hosted CI for the exact head was not observed. |

## Remaining gap

Fixing the live behaviour needs a platform change (for example fronting `/api/*` with a non-redirecting client action or an exclusion path with in-app authentication). That is an Azure estate change outside this task's authority and was not made. Follow-up: owner decision on the Easy Auth configuration.
