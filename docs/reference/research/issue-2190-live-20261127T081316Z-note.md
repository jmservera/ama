## Finding

Gate g2182 hung at `DemoTestCase.stop` -> `server.shutdown()` (`~/g2182/o/0052-project-api.log`, line 6003 onward) with the test itself already passed. The serving thread of the `_Server` classes sat in a blocking `accept()`: accept(2) states that a readiness event can outlive its connection, after which accept blocks until the next client. With no client left, `serve_forever` never re-checked the shutdown flag.

The hang was not reproduced: 400 consecutive solo runs of the test passed (316 s). The cause is therefore inferred from the stack, the stdlib source and the man page, not observed. The regression test proves the blocking property deterministically.

## Fix

`src/api/src/zava_forward/api/listener.py` adds `NonBlockingAcceptMixin` (non-blocking listener, accepted sockets forced back to blocking), applied to the three `_Server` classes in `server.py`, `resident_demo/app.py` and `resident_preview/app.py`. No timeout or check was relaxed.

## Evidence

* New tests `ShutdownDoesNotHangTests` pass with the fix. With the `setblocking(False)` line replaced by `pass`, both fail (`accept blocked with no pending connection`, 6.1 s).
* 145 tests in the resident demo, chat, resident API and preview modules pass; 30 tests for `server.py` (role matrix, regulatory chat, buildings) pass.
* `python3 -m mypy` in `src/api` and `ruff check`/`ruff format --check` pass. `rpi-checks.py --all` was not run (owner instruction); hosted CI is unobserved.
