* Active revision `ca-cutover-test-demo-api--0000150` (created 2026-11-27T19:21Z) runs `zava-forward-api:demo-337d3999d5`.
* The tag is a git short SHA. `git log -1 337d3999d5` resolves to the rubric score commit on `main`, and `git merge-base --is-ancestor c2213e0da4 337d3999d5` succeeds, so the audit-write retry of PR #2464 is in the deployed image. This closes the mapping gap recorded in the earlier note.

## Code change

The server answers a SQL write-lock timeout on `POST /api/chat/threads` with a handled 503 and `Retry-After: 5`, safe to repeat because thread creation is one insert and commit. The workspace script did not repeat it, so a person saw an error on the first send although the retry returned 200 (the 2026-11-22 symptom). `app.js` now repeats that one POST once after the `Retry-After` delay (capped at 5 s) with a plain-language status line, and never repeats another POST, a gateway 503 or a 500. Test: `test_chat_thread_create_retries_one_handled_busy_503` in `src/api/tests/test_workspace_scripts.py`.
