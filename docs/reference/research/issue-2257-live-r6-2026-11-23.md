## Change

The map's automatic redraw ran only when the error had no HTTP status, that is, a dropped connection. A non-JSON 500, 502, 503 or 504 (the page a gateway returns while a replica restarts) still carried a status once the three startup read retries (5 s in all) were spent, so the panel showed the notice and waited for a click. `api()` now sets `error.gateway` for such a read failure, using the existing `startupFailure` test, and the map schedules its one bounded redraw for it. A JSON error from the application is not marked and is still shown without a retry.
