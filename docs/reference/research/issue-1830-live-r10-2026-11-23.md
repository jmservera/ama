Scope: synthetic demo, FOCUSED tier. No live Azure (the issue forbids it), no `rpi-checks.py --all`, no change to `rpi-checks.py`. Builds on [r9](issue-1830-live-r9-2026-11-23.md).

## Gap and fix

Before the fix, `tools/rpi-gate-timing.py report` on a receipt that passed the sha256 and schema check raised `KeyError` (command without `argv`), `ValueError` (unparseable time) or `JSONDecodeError` (not JSON). A command whose `finished` preceded `started`, or a naive timestamp read in local time, was accepted silently and skewed the span and critical chain. Each case now exits 2 with `REFUSED:`.

## Evidence

* Reproduced the five cases before the fix with a throwaway script (tracebacks and silent acceptance).
* `python3 -m unittest test_rpi_gate_timing` in `tools/`: 22 tests OK; with the source fix stashed, 2 failures and 4 errors, so the two new tests detect the defect.
* `ruff check` and `ruff format --isolated --line-length 100 --check`: clean.
