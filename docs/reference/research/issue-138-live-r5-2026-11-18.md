## Scope and boundaries

Refs #138. Synthetic demo, desktop only. Only read-only GitHub and Azure commands ran; nothing was
created, dispatched or changed in Azure or GitHub, and no sign-in credential was read. No browser
proof applies because none of the six criteria has a user interface. Baseline:
[fourth run](./issue-138-live-r4-2026-11-18.md).

## Code finding

`summarize_plan` in `infra/scripts/pipeline.py` already rejects every `changeType` other than
`Create`, `Modify` and `NoChange`, so `Unsupported` entries are rejected. The existing test only
listed `Unsupported` among other kinds in a loop. The new test
`test_plan_rejects_unsupported_entry_among_valid_changes` accepts a valid three-entry plan, then
shows one added `Unsupported` entry makes the summary fail with the unsupported-change message.
Mutation check: allowing `Unsupported` in the code made two tests fail (the new one and the existing
loop test). `infra` pipeline tests: 33 passed (re-run in independent review: OK). Mutation output observed; raw output not retained.

The r3 and r4 follow-up "make summarize_plan accept Unsupported entries" is the opposite of this
task's goal. The live what-if (14 Unsupported, 81 Ignore) is still refused. Whether to tolerate those
entries is an owner decision and was not taken.
