Refs #2202. Synthetic desktop demo; read-only live checks on `ca-cutover-test-demo-api` revision 0000058 (Healthy, Running) and `ca-resident-demo` revision 0000028 (Healthy, RunningAtMaxScale), read with the Azure CLI on 2026-11-23. No Azure resource was created or changed. Sign-in values were read at run time and not recorded.

## Method

* `/api/map?sensors=1` loads sensor states for at most 100 homes per call (`sensor_map.HOME_CAP`), so earlier passes saw 343 of 443 homes as `not-loaded`. [probe_tiles.py](./issue-2202-live-2026-11-23/probe_tiles.py) quadtree-tiles the map extent until no tile holds a not-loaded home (16 tiles); new `tools/demo_readings_coverage.py` merges the tiles by home id and counts states. `tools/test_demo_readings_coverage.py` has 4 passing tests; ruff check and format are clean.

## Result

443 homes, all measured: fresh 254, stale 7, consent-withheld 94, no-readings 88, not-loaded 0. Homes with readings 261 (58.9%); fresh 254 (57.3%). The half-of-homes target holds with the lower bound rule. Data: [coverage-result.json](./issue-2202-live-2026-11-23/coverage-result.json), [tiles](./issue-2202-live-2026-11-23/tiles/).

Resident consent checkbox: on revision 0000028 `#assistant-consent` is visible, unchecked on open and checkable ([probe-live-result.json](./issue-2202-live-2026-11-23/probe-live-result.json), [screen](./issue-2202-live-2026-11-23/screens/resident-consent.png)).

## Limits

* Map gauges: the card probe did not open a home summary, so gauges stay unproven here. The overview screen is [staff-map.png](./issue-2202-live-2026-11-23/screens/staff-map.png).
* Snapshot time is a single moment; fresh means a reading within 15 minutes, so the fresh share drifts as simulator jobs run.
* Rollback, image provenance of simulator and receiver jobs, and generative answers (SUS-1, budget expiry) are not addressed here.
