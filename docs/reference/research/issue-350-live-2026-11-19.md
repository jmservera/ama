## Analysis

* Easy Auth decides before the request reaches the application, and chooses 401 or 302 from the client User-Agent. Source code in `src/api` cannot change it: the application's own 401 (`server.py`, unauthenticated API branch) and `/sign-in` redirect only run for paths Easy Auth lets through.
* The only fix is a different edge design: either `AllowAnonymous` with the application enforcing 401 for API and redirect for pages under a trusted platform-principal check, or a split of API and page hosts. Both change `infra/modules/containerapps.bicep`, `infra/scripts/setup-entra.py` and the deployed auth configuration.
* That is an infrastructure, deployment and security-control change (FULL tier). The 2026-11-18 owner authorisation excludes production changes and Key Vault rotation, and the issue itself requires a trusted platform-principal proof coupled to #349 before any API exemption. Not attempted.
