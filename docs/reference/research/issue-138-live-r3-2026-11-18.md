## Findings

* Variables: only `GH_AW_DEFAULT_MAX_DAILY_AI_CREDITS`. Secrets: only `COPILOT_GITHUB_TOKEN`. No
  `INFRA_PLAN_ENABLED`, `AZURE_*` or `DEPLOY_PARAMETERS`, so neither workflow can authenticate.
* Runners: 0, while the plan, release and deploy jobs request private labels.
* Environments: `copilot`, `dev-plan`, `test-plan`, `pilot-plan`, each with 0 protection rules and
  admin bypass allowed. The `dev`, `test`, `pilot` and `*-release` environments that
  `src-deploy.yml` targets do not exist.
* Runs: `infra-plan.yml` has 2510 runs, the latest `skipped` (its gate needs
  `INFRA_PLAN_ENABLED == 'true'`). `src-deploy.yml` has 0 runs.
* Federated credentials: 0 on each of the six user-assigned identities in `ama`. App registrations
  could not be read ("Insufficient privileges").
* What-if of the real `infra/main.bicep` with the `test` parameters (throwaway valid values,
  applications off): `Succeeded`, 99 Create, 15 Modify, 82 Ignore, 14 Unsupported. The pipeline's
  `summarize_plan` refuses it because of the Unsupported entries, so even the live plan would not
  produce an attachable summary today.
* `pipeline.smoke` passed against `ca-cutover-test-demo-api` (health 200 and three authentication
  denials) and raised `expected HTTP 200` for an unreachable host. Infra pipeline tests: OK.
* Secret scan: value-shaped patterns matched five test fixtures only; neither deploy workflow uses a
  `secrets.` context; the latest `Source projects CI` log (23777 lines) had 0 matches.

* Repository settings: variables, private runner, protected environments with reviewers and no admin

* Entra app registrations with per-environment federated subjects (the CLI identity lacks directory
  privilege).

  `*-cutover-test-*`, so a pipeline deployment would not update the demo in place.
