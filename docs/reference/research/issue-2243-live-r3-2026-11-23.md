Scope: synthetic demo, desktop 1440x900, resource group `ama`, owner decisions of 2026-11-18. Read-only on Azure: no estate change and no throwaway resource. Sign-in values were read from the owner file at run time and never printed.

## Diagnosis

The label is the fallback text for any failure that is not a named `AssistantUnavailable` reason (`_fallback` in `src/api/src/zava_forward/api/resident_demo/aoai.py`). It does not mean a reply failed verification.

* Endpoint env: `ZF_DEMO_ASSISTANT_ENDPOINT` on `ca-resident-demo` (revision 0000027) names `aif-cutover-test-rzsrg`; the account has public access disabled and a private endpoint. Model calls reach it: the console log carries `prompt_tokens=487 completion_tokens=9` and `302/59` lines.
* Deployment name: the code uses `resident-mini`; it exists (gpt-4.1-mini 2025-04-14, Standard, capacity 1, Succeeded).
* Cause: the deployment's rate limits are 1 request and 1000 tokens per 60 seconds (`az cognitiveservices account deployment show`, `rateLimits`). Azure metric `AzureOpenAIRequests` for `resident-mini` shows status 429 twice and 200 twice in the 11:30 UTC bucket. A second question inside a minute gets HTTP 429, raised as `urllib.error.HTTPError` (an `OSError`), which is caught and mapped to the generic label.
* Reply verifier: not at fault. Its failures have their own named labels (`invalid_output`, `invalid_answer`, `invalid_guidance`, `incomplete`).
* Limit of the proof: the exact 429 for the owner's earlier probe was not captured, because the fallback logged only the reason, not the exception class. The metric and limits make it the supported explanation, not a read of that call.

## Fix

`_fallback` now names the cause: HTTP 429 gives "the AI service is busy, so try again in a minute", other HTTP errors, URL errors and timeouts give "the AI service did not respond", unknown errors keep the generic label, and the warning log records the exception class name (never the message). The test `test_provider_throttle_and_outage_are_named_not_unverified` covers 429, 503 and timeout. Raising deployment capacity is an owner estate change and is not made here; a capacity of at least 10 (10000 tokens per minute) would remove the throttle for the demo.
