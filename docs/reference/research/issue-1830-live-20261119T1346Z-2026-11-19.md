## Method

Every command used the read-only analyzer `tools/rpi-gate-timing.py report <receipt>` on `~/.local/share/ama/gates/*/receipt.json` (sha256-bound, schema 4). Of 20 receipt directories, 8 are passed full receipts and were analysed; 12 were refused by the tool (failed or partial scope). Queue wait comes from the first line of the gate stdout log (`/tmp/gate*.log`) via `--log`; the receipt directories do not keep that line. The analyzer is observational and does not verify receipts.

## Findings

* Wall time equals the analyzer chain (span within 0.4 s of chain) in every receipt, so group durations were not added as wall time. Jobs-1 full receipts spend 2865 to 2927 s (about 48 to 49 min).
* Parallelism: at `--jobs 2` the summed command time doubles (5891 to 7642 s against about 2860 s) while wall time is 2788 to 3557 s. Commands run about twice as slowly under two jobs on this host, so the measured saving from `--jobs 2` is zero to negative. This is a descriptive observation across different heads, not a controlled experiment.
* Critical-chain heavyweights (jobs 1, g1258): API unittest discovery 808 s, core 530 s, SQL (mssql) 472 s, infra 152 s, browser 93 s. The longest chain groups are project-api, project-core, infra, mssql and browser. Per-project image builds after SQL form a serial tail of about 290 s.
* Setup (pip install and image build tokens) is 360 to 477 s per full gate, about 12 to 16 % of the summed time, and repeats per project virtual environment. That is the largest repeated-setup candidate.
* Suite growth: commands rose from 204 to 205 (7 to 8 November) to 217 to 218 (17 to 18 November) and the 1641-0235 core discovery took 1959 s against 1325 s in 470-0001 at the same job count. The cause (suite size, host load or both) is not separable from these receipts.
* Queue wait is about 0.001 to 0.002 s in the four measurable runs, so lock contention did not add elapsed time there. Elapsed time from repeated invalidated receipts is outside the receipt data.
* Mandatory versus candidates: every executed group is a required full-tier group and none is proposed for removal. Candidates for measured optimization, to be proven by a comparable before and after, are shared virtual-environment setup, the serial image-build tail and project test sharding. This note does not recommend a bypass.

## Defect found and fixed

`rpi-gate-timing.py report --log <missing file>` raised a traceback (reproduced with `/nonexistent`) where the tool's contract is `REFUSED` with exit 2. The fix refuses an unreadable or empty log; one test covers both cases.
