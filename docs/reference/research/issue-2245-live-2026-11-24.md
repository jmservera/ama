## Findings

* Thread creation: eight `POST /api/chat/threads` returned 200 (162 to 2283 ms), no 500 in this window ([probe-chat-result.json](./issue-2245-live-2026-11-24/probe-chat-result.json)).
* Five asks returned 200 (rules-first claim, sensor, two free-form case questions, one general question that abstained). All were `model: workflow-only`; none showed "Model calls: 1". The free-form replies say they use rules only because an open suspension holds AI answers.
* Banner: the widget and `/api/chat/status` disclaimer state "AI answers are on hold: an open suspension covers AI work, so replies use rules only" ([probe-widget-banner.json](./issue-2245-live-2026-11-24/probe-widget-banner.json), [widget-banner.png](./issue-2245-live-2026-11-24/screens/widget-banner.png)).
* Root cause of the remaining rules-only chat: revision 0000059 sets `ZF_DEMO_AI_SUSPENSION_OVERRIDE`, but `continuity.demo_owner_override()` returned False whenever `ZF_ENV=production`, and the live demo sets `ZF_ENV=production` (with `ZF_DEPLOYMENT_PROFILE=demo`). `SYN-221-PROBE` therefore still held chat ([probe-continuity-result.json](./issue-2245-live-2026-11-24/probe-continuity-result.json)).
* Fix (local commit, not deployed): the override now needs the dated owner token and `ZF_DEPLOYMENT_PROFILE=demo`; the suspension record stays open and the SQL `gate_hold` still wins. `test_demo_owner_override` fails on the old code and passes now; 15 core suspension-related tests and 45 `test_exception_register` tests pass; ruff clean. Core `mypy` reports the same 3 errors with and without the change (missing optional OpenTelemetry stubs, an unused ignore), so they are not caused by it.
