## Finding

`SqlStore._seed` opened `BEGIN IMMEDIATE` (on SQL Server, `sp_getapplock` on `zavaforward_write`, 15 s timeout) on every start, then ran `SELECT COUNT(*) FROM cases` and committed without writing when the table was populated. Earlier runs removed the lock from the schema, queue column and index steps, so this was one more start-up wait behind any long writer.

## Change

`_seed` counts `cases` first, without the lock, and returns when the table is populated. The locked path is unchanged and still re-counts, so two concurrent first starts on an empty database cannot both seed. Test `test_populated_cases_skip_the_seed_lock` in `src/core/tests/test_mssql_startup_lock.py` fails without the change and passes with it (18 tests OK; `test_sqlstore` plus the lock tests 39 OK).

Still locked on every start: `_migrate`, `_migrate_recommendations`, `_ensure_queue_membership`. They compute derived data and need their own read-only currency checks; left as follow-up.
