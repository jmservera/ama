## Root cause of the open criterion

The clock fails closed in `hazard_clock` (`src/core/src/zava_forward/core/taskqueues.py`) when `aware_at` or `response_due_at` is absent. The generated demo hazards never carried those fields. `SqlStore.merge_seed` is insert-only, so a re-seed of identical case ids cannot update stored hazards, and a re-seed that produces changed hazard content aborts as a conflict. The generator of the 980-case demo dataset is not in this repository, so no source fix can add the fields at generation here; the repository path is `infra/scripts/seed_demo_hazard_clock.py` (4 unit tests and ruff pass, re-run 2026-11-23). It is idempotent and reversible.
