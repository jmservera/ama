## Why no source change

The clock fails closed in `hazard_clock` (`src/core/src/zava_forward/core/taskqueues.py`) when `aware_at` or `response_due_at` is missing, so the original defect was missing data, fixed by `infra/scripts/seed_demo_hazard_clock.py`. The clock logic is already covered by `src/api/tests/test_workbench_hazard_clock_owner.py`. `SqlStore.merge_seed` is insert-only, so the seeded values persist across restarts; a destructive re-seed, or a generator change outside this repository, is owner-gated.
