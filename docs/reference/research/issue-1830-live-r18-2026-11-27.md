Scope: synthetic demo, desktop only. No live Azure (the issue forbids it), no secrets, no push. Follows [r17](issue-1830-live-r17-2026-11-27.md).

## Findings

Opening state; results appended below after reproduction.

* Retained receipts on this host: `/tmp/r2188/receipt.json` (scope partial) and `/tmp/r2188t/receipt.json` (receipt.sha256 missing). `rpi-gate-timing.py report` refuses both (`Only passed schema 4 full-scope receipts are analysed`, `receipt.sha256 is missing or does not match`). No verified full receipt, and so no multi-receipt critical-path measurement, is available.
* Defect, reproduced: a hash-valid full receipt whose commands include two zero-length commands at one instant (`a` and `b` at +5 s, plus `c` from 0 to 3 s) made `rpi-gate-timing.py report` run until killed (15 s timeout hit, no output). `critical_chain` keeps commands with `end <= current.start`, so `a` selects `b` and `b` selects `a` forever, while the `steps` list grows.
* Fix: choose only commands that sort strictly before the current one on `(end, start)`, which guarantees the walk ends and keeps every legitimate predecessor.

## Result

* Before: report hung (15 s timeout). After: exit 0, `chain_seconds` equals `span_seconds`. `tools/test_rpi_gate_timing.py` 25 tests OK; the new test fails (30 s timeout) when the fix is stashed. ruff format and check clean.
