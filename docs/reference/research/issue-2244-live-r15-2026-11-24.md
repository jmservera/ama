Scope: synthetic demo, desktop only, resource group `ama`, owner decisions of 2026-11-18. No sign-in value was read and no browser proof applies because the defect is a start-up path with no UI. The live database `retrofit` and the live API were not touched. Refs #2244. Earlier runs: [run 9](./issue-2244-live-r9-2026-11-24.md), [first run](./issue-2244-live-2026-11-23.md). The issue has no tick-box list; criteria C1 to C5 are those derived in the first note.

## Method

* `az sql db copy` made `tmp-2244-lockproof` (S0) on the same server from `retrofit`. The public network is disabled, so the test ran inside the Container Apps environment.
* Three throwaway jobs ran the deployed API image (digest `7610c41b...`, API revision 0000068) with the API managed identity. The proof script [lock-proof.py](./issue-2244-live-r15-assets/lock-proof.py) refuses the name `retrofit`, takes the same `sp_getapplock` write lock on the copy from a second connection, then opens `MssqlStore` and reports how long it took.
* The installed package is read-only, so the new code ran from a copy placed first on `sys.path` (script prints `OVERLAY`), after printing the image file hashes. The image hash of `sqlstore.py` (`39cce3ced2ce`) equals the main checkout, so the overlay differs only by this change.
* All jobs and the database copy were deleted afterwards; the live API stayed on revision 0000068, Healthy, `/healthz` 200.

The trace line `BEGIN requested by execute < _migrate < _initialize` shows the remaining lock taker: `SqlStore._migrate` took the write lock on every start-up and rewrote the continuity hold rows, even with nothing to change. The existing fast paths (schema, queue columns, indexes, chat memory, recommendations) were correct, but the retry budget (8 attempts of 15 s plus 1, 2, 4, 8, 16, 30 and 30 s backoff, about 211 s) is the only protection for this step, so any writer longer than about 3.5 minutes still took the API down. That matches the 12 minute outage of 2026-11-22.

## Change

* `continuity.gate_in_sync(db, mssql=)`: read-only check that `sync_sql_gate` would change nothing.
* `SqlStore._identity_drift()`: read-only generator extracted from `_repair_identity_columns`, behaviour unchanged.
* `MssqlStore._migrate_current()` and `_migrate()`: skip the lock when derived columns, rank policy, support encoding, identity columns and the continuity gate are all current; any doubt takes the unchanged locked path.
* Unit tests in `src/core/tests/test_mssql_startup_lock.py` (`MigrateFastPathTests`).
