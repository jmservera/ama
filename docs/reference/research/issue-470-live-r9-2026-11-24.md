## Reading the numbers

* The suite grew: a serial full run now takes about 2900 s (48.8 min) against the 23 to 26 min recorded on 2026-10-27, so the "before" and "after" arms are not like for like. The growth is not separated from host load.
* The fastest retained full run (jobs 4, 2402 s, 40.0 min) is 18 percent below the serial receipt of the same era (2926.9 s). Jobs 2 runs were not faster than serial and each command ran about twice as slowly; wall time followed host load (4500 and 5297 s on 19 to 20 November).
* Every receipt differs in head, base and load, so `tools/rpi-gate-timing.py compare` refuses a pairing as non-comparable. The 18 percent is a descriptive pointer, not a measured speed-up.
* Host at this run: load average 7.45 (4 vCPU) and `/tmp/ama-rpi-heavy.lock` present, so a new measurement here would be invalid even if `--all` were permitted.
