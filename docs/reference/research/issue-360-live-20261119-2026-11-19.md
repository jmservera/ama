## Why no code change

The first unmet criterion, c, is an owner approval, not behaviour. The one code-adjacent gap under d, the browser-mode 302, comes from Easy Auth `unauthenticatedClientAction` `RedirectToLoginPage` in `infra/modules/containerapps.bicep` (line 302). Changing it alters an authentication control and deployment configuration, which requires the FULL validation tier and a verified external receipt; it also changes how browser sign-in redirects work. That is outside a focused run, so it is reported as an open follow-up rather than edited. No box on #360 is ticked by this note.
