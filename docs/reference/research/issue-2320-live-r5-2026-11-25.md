## Cause

`Store.briefing` caches by `self.version`. Any write by another client invalidates the cache, and the miss path then runs `run_text_task` and `self.audit`, which write under the SQL write lock (`sp_getapplock`, 15 s wait with retries). When another client holds the lock the GET fails with 503, or waits many seconds first. The #2358 change only covers a repeated GET while the version is unchanged.

## Fix (not deployed)

`Store.briefing` now catches only a write-lock-busy driver error from the recording step and returns the last cached answer, or a read-only rules summary, with `recorded: false` and a plain-language reason. Other errors still raise. The test `test_briefing_answers_without_503_when_recording_hits_a_busy_write_lock` in `src/api/tests/test_assistant_release.py` injects the busy error. The fix cannot be re-proven live until it is merged and deployed; this task does not push.
