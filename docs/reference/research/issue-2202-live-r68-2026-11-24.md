## Evidence

* Revisions and hardening ([az-state.txt](./issue-2202-live-r68-2026-11-24/az-state.txt)): API `--0000068` and resident `--0000030` are Running or RunningAtMaxScale, Healthy, 100% traffic, Single revision mode. Agents `--0000004` is ScaledToZero and Healthy (minimum replicas 0, no external ingress). `ZF_CONTAINER_HARDENING=enforced` is set on API, resident, agents and on both live jobs. Simulator and receiver jobs run the same API digest and recent executions Succeeded; the 16:30 receiver run was still Running at read time.
* Sensor charts: 50 of 50 case sensor endpoints returned 200 and 30 homes had at least two readings. The Home sensors tab on `ZF-2025-0331` renders a two-axis chart with 12 readings, solid line and circles for temperature, dashed line and squares for humidity, an `aria-describedby` summary, a readings table with 12 rows, no running animation and no horizontal overflow ([live-chart-probe.json](./issue-2202-live-r68-2026-11-24/live-chart-probe.json), [screenshot](./issue-2202-live-r68-2026-11-24/live-home-sensors-chart.png)).
* Map gauges: the map shows 443 homes. Selecting a home opens a card with two `meter` gauges (temperature 11 degC on a 0 to 40 scale, humidity 79.4 %RH on 0 to 100), a text value, a recent-reading status and no animation ([live-map-card-probe.json](./issue-2202-live-r68-2026-11-24/live-map-card-probe.json), [screenshot](./issue-2202-live-r68-2026-11-24/live-map-card-gauges.png)). The first gauge probe in this pass found none because it looked for readings in marker labels, which are filled only under the "stale or offline" filter; selecting a home is the path that loads them.
* Consent checkbox: on the resident site `#assistant-consent` is visible, unchecked on open and checkable ([probe-live-result.json](./issue-2202-live-r68-2026-11-24/probe-live-result.json), [screenshot](./issue-2202-live-r68-2026-11-24/screens/resident-consent.png)). The probe's `label[for]` selector returned no text, so this note makes no claim about the accessible name.
* Chat routing: six employee-chat questions each returned a routing line with no HTTP error and no retry: quality, funding and stock go to the matching specialist; the quality plus funding question and the general question go to the General agent with the reason given; "Approve the funding claim" is refused as a human action ([live_routing_probe.json](./issue-2202-live-r68-2026-11-24/live_routing_probe.json)). The outcome for each was workflow-only help because the daily demo allowance for AI answers was used up, so this proves routing and refusal, not generative answers.
* Half of homes with readings: all 16 map tiles merged by `tools/demo_readings_coverage.py` give 443 homes, 262 with readings (59.1%), 257 fresh (58.0%), 93 consent-withheld, 88 no-readings, 1 offline, 4 stale, 0 not loaded ([coverage-result.json](./issue-2202-live-r68-2026-11-24/coverage-result.json)). The target of half holds. The fresh share drifts as the simulator runs.
