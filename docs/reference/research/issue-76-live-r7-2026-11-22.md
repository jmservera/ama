Refs #76. Synthetic desktop demo under the owner decisions of 2026-11-18. No Azure resource was created or changed, so nothing needed deleting. The staff test credentials were read at run time only. Nothing here is production evidence.

## Gap found

Earlier passes proved the owner and a safeguarding clock live, and found the hazard clock "Unknown". The cause was in code: `taskqueues.context()` built the queue and case-card clocks without the target-clock projection, so "time remaining" or "overdue" text never reached queue rows or the "Recorded task context" block. Only the hazard list carried it. The old text also showed overdue items as "-6h remaining".

## Change

* `taskqueues.clock_fields()` merges the target clock (label, status, hours remaining, deadline) and named or escalation owner into every hazard and safeguarding clock. A safeguarding label becomes "Safety review clock" for roles without reason visibility.
* `app.js` shows plain text: "N hours remaining until the target", "Overdue by N hours", "Completed", or "Time remaining unknown: the time the team became aware is not recorded. Next action: record it so the clock can run". Status is always words, not colour.
* A date-only `noticed` value still fails closed; the product states what is missing and the next action instead of inventing a time.
