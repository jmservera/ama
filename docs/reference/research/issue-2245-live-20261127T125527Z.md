## Source change

After the answer save, `ChatPanel._ask.finish` (the `chat.answer` audit) and `ChatPanel.ask` (the `chat.turn` audit in the finally block) wrote under the SQL lock with no retry, so a lock timeout there would turn a saved, paid answer into a 500. Both now use the same bounded retry (two more attempts) as the question and answer saves; a persistent timeout still raises, so no audit is dropped silently. Test: `test_audit_writes_retry_a_write_lock_timeout_after_the_answer_saved` (fails against the previous file, passes now; 210 `test_chat*` tests pass). Not deployed; this path was not seen failing live.
