Scope: synthetic demo, desktop only. Tier FULL for the coordinator (a file under `src/api` changed); `rpi-checks.py --all` was not run. No live Azure (the issue forbids it), no secrets used, no push. Follows [r11](issue-1830-live-r11-2026-11-24.md).

## Findings

* Reproduced at head: direct `checks/map_fullscreen_browser_check.py` (axe-core 4.10.3, sha256 prefix `880970c081707360`, matches the pin) failed `filter label and focus fit at 390x568` in 2 of 4 reruns at load average 20 to 27 and passed in 2.
* Cause, observed with a throwaway wrapper in `/tmp` that printed the measured values only on failure: the outline was `solid`, tile height 126 px and width conditions held, but after `focus()` scrolled the tile inside the scrollable filters box, the tile bottom was 322.17 px against a box bottom of 322 px (0.17 px over). Two other failures showed 321.78 against 322, which passes, so the position varies by sub-pixel scroll rounding. Real clipping would be many pixels.
* Fix: the containment test in that check allows 1 CSS px (`r.top >= p.top - 1 && r.bottom <= p.bottom + 1`). Six reruns passed at load 9 to 12 (lower than during the failures, so this is not proof under load above 20).
* `ruff check`, `ruff format --isolated --line-length 100 --check`, `python3 -m mypy` in `src/api`: clean. 62 timing and preflight tests OK; `rpi-checks.py --preflight api:test_production_config_a11y_check` passes and labels the result development feedback, and `api:test_does_not_exist` is BLOCKED.
* The script is not referenced by the scenario manifest, so no recipe hash changed.
* An earlier batch of six runs at load 33 to 42 failed before any browser step with `Local synthetic server did not become healthy`: the 10 s server start window is too short under that load. This is host contention, not changed here.

## Criteria

Criterion 2 is proven for the demo apart from load above 20 (not rerun). Criteria 1, 3 and 4 are unchanged from r11; see the changes record.
