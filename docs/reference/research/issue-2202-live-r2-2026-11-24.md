## Receiver execution Failed at 20:00 UTC

`job-live-receiver-29925840` ended Failed. Of the 12 most recent executions it is the only one; 10 Succeeded and one was still Running. Log Analytics (`ContainerAppSystemLogs` and `ContainerAppConsoleLogs`) show the container terminated with exit code 2 at 20:25:33, and the console line `Cannot run: RUN_STOPPED`. The receive window is 1500 s from 20:00:30, so the stop fell at the window edge, not during it.

Source reading of `src/api/src/zava_forward/api/iot_stream.py` shows the cause that matches this timing. In a bounded window an event callback that runs after the deadline raised `StreamError("RUN_STOPPED")`, which was recorded as a run failure and turned into exit code 2, although the same file treats the deadline as the normal end of a window for a write in flight (`IOT_OPERATION_TIMEOUT`). Which of the two edge causes occurred in the live run (an event landing after the deadline, or the control watcher firing at control expiry) cannot be told from the retained logs, so the diagnosis is probable, not proven. The fix makes only the deadline case a normal end; a stop requested through the control watcher still raises `RUN_STOPPED`. The new regression test fails without the fix (`RUN_STOPPED`) and passes with it. The fix is a local source change and is not deployed: no image build or rollout was in scope.
