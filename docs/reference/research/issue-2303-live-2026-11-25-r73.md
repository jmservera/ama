## Where the time goes

Timings inside the replica (exec, results only):

| Step | Seconds |
| --- | --- |
| `ai_eval` / `chat_eval`, first call | 1.4 / 1.9 |
| the same, cached | 0.0 |
| consumption report (SQL) | 2.7 |
| held-out suite, tokenomics comparison | under 0.2 |
| `ai_live_report` without a user | 1.0 |
| `ai_live_report` with a user and assistants service | 68.5 |

`live_report` calls `projection.withheld_scope_values` for every Edited or Rejected recommendation. The demo holds 42 of them (of 2,791), each call scans all 980 cases (about 1.9 s), and the 42 share only 3 distinct case sets.

## Fix (source, not deployed)

`ai_tasks.live_report` now computes the withheld values once per distinct ordered case set within a call. The result depends only on the user, store state and case set, all fixed during one call, so output and redaction are unchanged. Expected cost: 3 scans instead of 42, so the live report falls from about 68 s to about 6 s and the endpoint to roughly 10 s. This estimate is not measured on the live app.

Test `src/core/tests/test_live_report_withheld_scan.py` counts scans (2 for 4 recommendations over 2 case sets); it fails with `4 != 2` against the old code. The 607 core tests that reference `ai_tasks`, `ai_live_report` or `reviewer_reasons` pass.

## Not proven

* Live latency after the fix: needs a new image and revision. The brief did not authorise a deployment, and the ACR is not reachable from this host.
* Full tier gate and external receipt: the coordinator owns them.
