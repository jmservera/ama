## Code change

`run_live_check._select_budget` now accepts the budget whose `ResourceId In` filter contains the hub resource id (case-insensitive) and falls back to the name `budget-<hub>`. This closes the follow-up routed by the earlier review. One new test in `src/core/tests/test_run_live_check.py` covers a differently named, scope-matched budget and a budget scoped to another resource.

## Live run

Method: a throwaway Container Apps job `job-189r5-probe` in `cae-cutover-test-demo` ran the deployed demo API image as `id-cutover-test-api`, with a temporary IoT Hub Registry Contributor role on the hub. The driver stayed outside the repository. It wrote a `live_control` document (owner taken from the hub `owner` tag, approval reference, expiry 150 seconds after start), then ran the repository `live_simulator.run` loop with a one-minute cadence, the control gate on every slot and send attempt, and a sink that registers devices with Hub-generated keys and sends over HTTPS.

Raw job output: [job-output-raw.txt](./issue-189-live-r5-2026-11-19/job-output-raw.txt). Two earlier executions failed before sending (adverse, not retained: first an image-start failure with no replica, then a managed identity token scope error for `iothub.azure.net`; the data-plane resource is `iothubs.azure.net`).

| Observation | Result |
| --- | --- |
| Run owner | control document accepted with a named owner (`owner_set True`); blank or placeholder owners are refused by `live_control.parse` (unit tests) |
| Time limit | expiry 10:50:41Z; the loop sent 3 slots, 9 messages (204 each), then at the next slot the gate returned expired and nothing more was sent; `decision_now expired`, ended 19.1 seconds after expiry |
| Cleanup | 3 of 3 devices deleted (204); job deleted; temporary role removed and re-listed as absent |
