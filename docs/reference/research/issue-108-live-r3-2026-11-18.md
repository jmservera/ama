## Results

* Deployments (both `Succeeded`): `resident-mini` gpt-4.1-mini 2025-04-14, Standard, capacity 1, 1 request and 1,000 tokens per 60 s; `standard` gpt-4.1-nano 2025-04-14, GlobalStandard, capacity 10, 10 requests and 10,000 tokens per 60 s. The uksouth account has public network access disabled, the swedencentral one enabled.
* Quota headroom: both usages routes return an empty list in both regions. `az quota` and `Microsoft.Quota` fail with `MissingRegistrationForResourceProvider` (subscription not registered). Registering the provider is a subscription change outside the authorised scope, so it was not done.
* Live `/api/ai/report` returns 200: 11 scenarios, all passed; 16 consumption calls today, 1 failure, 1 unknown liability, coverage `incomplete` (historical calls and independent resident accounting are not joined). Live task counts show 0 AI-sourced items; fallback reasons include release admission denied (216), suspension SUS-1 (128), "AI is not configured" (14) and workflow-only mode (9). This is evidence that the release gate and suspension hold on the demo, not of model quality.
* `/api/ai/heldout-evaluation`, `/api/ai/cohort-evaluation` and `/api/ai/candidate-comparison` return 403 "Your role does not include this." for the Programme Manager account, as in the previous round. They remain unexercised live. The source handler lists Programme Manager among manager roles for a related route set, so the role mapping on the deployed build is worth a separate check; it was not investigated because no source change is in scope.
