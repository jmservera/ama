Scope: synthetic demo, desktop only. No live Azure (the issue forbids it), no secrets, no push. Gate tool edit classified FULL by doubt; `rpi-checks.py --all` not run. Follows [r16](issue-1830-live-r16-2026-11-27.md).

## Findings

* New angle: analyzer input handling. Synthetic schema 4 full receipts with a valid `receipt.sha256` but one header field removed made `rpi-gate-timing.py report` end in an uncaught `KeyError` (`jobs`, `image_cache`, and `sealed` when `--log` was given). `compare` indexed `sealed` the same way. Earlier rounds had only hardened the command bodies.
* Fix: `load_receipt` now refuses a missing or non-positive `jobs`, a non-string `image_cache` and a missing, unparseable or naive `sealed` with exit 2 and a `REFUSED:` message.
* Before: traceback (replayed for all three fields). After: `REFUSED: Receipt jobs is missing or invalid`, `REFUSED: Receipt image_cache is missing or invalid`, `REFUSED: Unparseable command sealed time: None`.
* Tests: new `test_hash_valid_receipt_missing_header_fields_is_refused` (5 subtests); `tools/test_rpi_gate_timing.py` 24 tests OK; ruff format clean. The synthetic receipts lived in /tmp and were deleted.
