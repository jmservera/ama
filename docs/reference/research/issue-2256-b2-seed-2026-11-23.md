Scope: synthetic demo, desktop, resource group `ama`. Refs #2256. Sign-in values were read at run time and not printed. No Azure change and no resource created. Follows [the earlier note](issue-2256-live-2026-11-23b.md).

## Finding

The generated demo seed is private and not in the repository. It recorded the offers ZF-2025-0029 to 0032 with `offered_at` as a wall time without a timezone and `due_at` null. `handoff_ageing` and `handoff_sla` in `src/core/src/zava_forward/core/workflows.py` show such a time as unknown instead of guessing, and that stays: the API must not invent times. The data is the defect.

## Change

`src/core/src/zava_forward/core/demo_handoff_due_seed.py` (inspect, apply, revert; run like `seed_merge.py` with `ZF_STORE=sqlite|mssql`) follows the #2255 precedent. For a pending handoff whose `offered_at` has no timezone it:

* reads the wall time as Europe/London (synthetic-demo assumption; 2026-10-13 is BST, so `09:00` becomes `09:00+01:00`);
* writes `due_at` only when absent, as the offer plus a labelled 72-hour demo window, in UTC (not the OD-09 approved limit, which is undecided);
* marks the handoff `demo_due_seed` with the original value so `revert` restores it exactly, and writes an audit entry;
* never edits `handoff_history`.
