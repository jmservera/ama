\paragraph{Tool settings and repeatability.}
The public host configuration requests Lizard, jscpd and Ruff; per-run
configuration and version records, not package presence alone, establish
the tools actually used. The declared pins are Lizard 1.24.3, Ruff 0.17.3
and jscpd 5.4.1. The code records backend names and supports explicitly
different internal approximations; these are not interchangeable instruments.
Lizard measures each Python source function. jscpd runs from an empty
configuration directory in Python mode with minimum 50 tokens and five
lines. Ruff runs with isolated configuration, fixed
\texttt{E,F,W,C90,B,SIM} selection, JSON output, no cache and
\texttt{--exit-zero}; diagnostics are counted rather than treating its exit
code as a clean-lint verdict.

The actual invocation omits \texttt{--ignore-noqa}, so inline suppressions
remain effective. No suppression-count field or maintainability-index
field appears in the active dictionary. An installed dependency or
qualitative review phrase must not be reported as a measured variable.
With no detected functions the engine emits zero mean/maximum/share
summaries; these are empty-input sentinels, not measured zero complexity,
and the mean/share denominator is undefined.
The measurement engine, collector, pilot analyzer, failure-attribution
module and C prompt have identical source blobs in the three disclosed
implementation epochs. This does not make the whole evolving dataset a
single frozen implementation or establish equal execution conditions.

\paragraph{From observations to summaries.}
The collector evaluates at feature and retained post-step checkpoints, and
again after CR1. A/D have no separate post-step; B/C/E retain their assigned
post-step. It writes outcomes, provenance, source HEAD, raw metrics,
integrity and diff records. The current final score is unavailable when
sequence/panel identities or binary endpoint observations are incomplete.
The loss/CR1 reporting gaps in Section~\ref{sec:decaymeasurement} remain
explicit rather than being filled with invented data.
Credits require complete consumption flags; all-attempt delivery/CR1 totals
need a matching attempt journal. Aggregate statistics and seeded resampling
operate on these records, not on AI opinions. Model-specific allocation,
missingness and observed runtime variation remain distinct from whether
the scoring algorithm is programmatic.

\subsection{Active AI review and consolidation prompt examples}\label{app:activeprompts}

These are the exact checked-in B/C templates at the active source commit,
not a new judge prompt, a protocol amendment or a complete per-session
provider request. The runner removes HTML-comment lines and the first
Markdown heading, substitutes the configured post-step budget in minutes,
and saves the actual supplied text as the step's \texttt{prompt.md}.
The public configuration has a 900-second post-step budget, rendering
``15 minutes''; this inspection does not verify every private run's rendered
prompt or provider/system context. Each step is a fresh session under its
assigned study model/effort. The model can reason qualitatively over the
visible report and diff, but hidden outcomes are measured outside it.

Arm B requests behaviour-preserving changes and structural stopping
targets. Arm C requests a 300-word issue-oriented \texttt{REVIEW.md}
without code/test changes. The host enforces the permitted-file and
retained-test rules; it does not parse either note into a numerical quality
score. Reviewer disagreement is therefore treatment variation, not a
measured inter-rater reliability or calibrated-judge result.
The template's ``optional placebo'' heading is retained verbatim; this
manuscript treats C as information-bearing review, not an inert placebo.
The historical v4 prompt in Section~\ref{app:prompt} remains a separate
unchanged source record.
