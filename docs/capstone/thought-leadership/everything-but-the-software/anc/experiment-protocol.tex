inherited by later feature work. RQ3 is addressed by a five-arm exploratory
study now in execution. Agent configuration protocols and empirical-study
guidance informed its earlier planning

\subsection{Development and evaluation execution boundaries}\label{sec:runtimeboundaries}

The pinned runtime separates model transport from candidate-code execution
(Figure~\ref{fig:runtimeboundaries}). The trusted host runs the Python
experiment controller and JavaScript Copilot SDK/CLI transport. Prompt
preparation and the authenticated model connection remain on that host.
The development model can request \texttt{isolated\_exec}; a Python broker
runs each requested command in a fresh isolated container, returning bounded
stdout, stderr and exit status through the transport to the model.
Validated filesystem/Git state is replayed into a fresh writable isolated
workspace for the next call; this is not a persistent container or writable
host checkout. Candidate processes and memory do not persist, while
host/model conversation context is not reset by that boundary.
Only validated committed regular content crosses feature/CR checkpoints;
the host canonicalises history rather than retaining arbitrary actor
commit metadata.
Visible-test verification and hidden measurements use separate evaluator
containers after development steps.

The supplementary post-run path begins with a stopped local study archive.
Host Python selects recorded checkpoint HEADs and asks the broker to replay
fixed API workflows through \nolinkurl{judging/execute.py}.
Candidate snapshots and evaluator code are mounted read-only.
Bounded observations, failures and errors become anonymised evidence
packets. Host Python then invokes the configured adapter; the JavaScript
\nolinkurl{copilot-judge.mjs} establishes a separate tool-free Copilot
session. The judge receives the packet and returns ordinal ratings,
rationales and evidence citations for host-side validation and reporting.
It has no command tools or candidate-repository access. Its model connection
is outside the replay container; candidate isolation does not place the
AI judge or host orchestration inside that sandbox.

The broker's candidate-execution containers disable networking, use a
read-only root filesystem and set \texttt{no-new-privileges}, with CPU,
memory, process and time limits. Docker uses \texttt{--cap-drop=ALL}
but re-adds four for its protected supervisor; the candidate child runs
as UID/GID 1001 with cleared effective, permitted and inheritable
capabilities. The entire container is therefore not capability-free.
Development workspace mounts remain writable; replay snapshot/evaluator
mounts are read-only. Copilot authentication stays with the trusted host transport.
An isolation or collection failure leaves the checkpoint unavailable.
A successfully collected candidate failure remains failure evidence,
rather than automatically becoming unavailable or a numerical zero rating.
These boundaries describe inspected source contracts, not an adversarial
integrity proof or verification of every archived execution epoch.

\subsection{Outcomes and retained-contract loss}\label{sec:decaymeasurement}

The primary outcome is final behavioural coverage: contracts passed out
of all 127 scheduled feature contracts at $P_{10}$, before CR1.
Coverage combines acquisition, retention and repair.
Retained-contract loss and CR1 adaptation are distinct secondary outcomes,
with legacy identifiers H2 and H6 retained only for data traceability.
HIR/IDR definitions are in the supplementary appendices;
comprehension is not measured.

\paragraph{Who measures, and what ``quality'' means.}
The running kit at \texttt{e71037d9} does not call a separate LLM-as-judge
to assign numerical outcome scores. The experiment models produce features, consolidation,
review notes or repairs; these are treatments, not independent measurement
instruments. The host evaluator runs fixed hidden test contracts and
external code-analysis tools, writes \texttt{measure.json}, and computes
summaries from those records. Table~\ref{tab:measurementprovenance} separates
outcomes, structural proxies and resource observations.
``Behavioural coverage'' is a test-contract pass fraction, not instrumented
line or branch coverage. Complexity, duplication and lint do not constitute
a general architecture, readability or comprehension score; the active
metric dictionary contains no maintainability-index score.

\paragraph{AI review is a treatment, not an outcome judge.}
Arm C's model reads \nolinkurl{reports/quality.md} and the feature diff, then
rewrites \texttt{REVIEW.md} in at most 300 words using a checklist of
duplication, complex functions, names, dead code, responsibilities and
behaviour-focused tests. Those qualitative judgements may vary between
model sessions, but the kit does not convert them into a numerical review
or quality score. Arm B uses a similar checklist to guide changes.
Its complexity $\leq10$, duplication $<3\%$ and zero configured-lint-warning
targets are requested stopping conditions and treatment-fidelity checks.
\texttt{make check} runs tests and generates the metrics report; the report
writer does not itself assert that all three structural targets are met.
The runner enforces the time budget, protected tests and retained green
code, rather than accepting an AI statement as an independent quality verdict.
The exact checked-in B/C examples, parameter substitution and saved-prompt
limitations are in Supplement Section~\ref{app:activeprompts}.

For trajectory $r$, $F_t$ is the retained state after feature step $t$ and
$P_t$ the state after its assigned post-step; these source states coincide
in A and D. Let $\mathcal{R}_{r,t}$ contain eligible, unchanged contracts
that passed at least one earlier end-of-cycle checkpoint $P_u$, $u<t$.
Superseded contracts leave this risk set. At $F_t$ and $P_t$, let
$\mathcal{O}^{p}_{r,t}\subseteq\mathcal{R}_{r,t}$ contain contracts with
observed binary results $S^p_{r,t}(q)$, $p\in\{F,P\}$. Report
\begin{equation}
L^p_{r,t}=\sum_{q\in\mathcal{O}^{p}_{r,t}}
\mathbf{1}\{S^p_{r,t}(q)=0\},\qquad
d^p_{r,t}=\frac{L^p_{r,t}}{|\mathcal{O}^{p}_{r,t}|}.
\label{eq:decayloss}
\end{equation}
The density is checkpoint prevalence of failure among observed,
previously acquired contracts. An empty observed denominator is undefined.
These summaries require known full-risk membership. If earlier acquisition
checkpoints leave membership uncertain, retain that uncertainty and the
checkpoint vectors rather than treating unobserved acquisition as failure
to acquire.
Publish the full risk set, observed subset and missing count
$M^p_{r,t}=|\mathcal{R}_{r,t}|-|\mathcal{O}^p_{r,t}|$ alongside it.
The full-risk loss count lies between $L^p_{r,t}$ and
$L^p_{r,t}+M^p_{r,t}$; missing evaluations cannot be treated as passes.
Never-acquired contracts remain acquisition failures.
Retain onset, recovery, recurrence and uncertainty across missing
checkpoints. Recovery does not erase an episode. Distinguish same-cycle
post-step losses and rejected attempts from losses in retained code.

\subsection{Replication and uncertainty}\label{sec:protocollimits}

The 2 November planning record offers $n\in\{12,21,33\}$ independent
repository trajectories per model per arm, with \textbf{12 as the default};
current execution selects 21. That record calls for the choice, rationale,
planning SD, power/precision trade-off, date and source-bound configuration
to be recorded before collection. It does not establish that the current
amendments were prospectively registered. Selecting a sample size does not
establish that its associated SD assumption is true.
The saved allocation is immutable on resume. Outcome-driven sample-size
changes, additions and replacements are prohibited; interim coverage,
loss, CR1 success or other outcomes cannot determine $n$.

Servera Bondroit selected a minimum useful absolute coverage gain of ten
percentage points, approximately thirteen test-weighted contracts.
Coverage scores $Y$ are expressed on the 0--100 scale. Let
$\overline{Y}_{ma}$ be mean final coverage for model $m$ and arm $a$.
The primary estimand is the equal-model-weight difference in mean coverage
over the $M=3$ selected models. Its estimator is
\begin{equation}
\widehat{\Delta}_{BD}=\frac{1}{M}
\sum_{m=1}^{M}(\overline{Y}_{mB}-\overline{Y}_{mD}).
\label{eq:primarycontrast}
\end{equation}
For balanced cells of $n_{\mathrm{cell}}$ independent trajectories and a
common within-cell variance $\sigma^2$, its planning variance is
$2\sigma^2/(M n_{\mathrm{cell}})$, with $n_{\mathrm{cell}}=n$.
For one two-sided comparison with $\alpha=0.05$, target power
$1-\beta=0.80$ and target difference $\Delta_*=10$ points, the normal
planning minimum, conditional on the assumed SD, is
\begin{equation}
n_{\mathrm{plan}}(\sigma)=
\left\lceil\frac{2(z_{1-\alpha/2}+z_{1-\beta})^2\sigma^2}
{M\Delta_*^2}\right\rceil.
\label{eq:samplesize}
\end{equation}
