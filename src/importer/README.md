The importer (`zava_forward.importer`) is the quarantining import workload described in ADR 0001. The former `mvp/` application had no import service, so the former `mvp/README.md` had no importer content to move in M6 of #199. The project holds the Excel transition library of #80 (below), a `python -m zava_forward.importer` entry point and its tests.

* Fixtures: `evals/document_form_fixtures.json` (document-form fixtures, registered in `src/agents/evals/registry.json`) with its test in `tests/`.
* Boundary: the project imports `zava_forward.core` only (the document controls and scanner live in `core`, `doc_controls`); no project imports it. Dependency rule tests are in `tests/test_dependency_rule.py`.
* Excel transition (#80, synthetic data only, standard library only): `xlsx` (read-only reader with size, entity and formula-injection guards, values-only writer), `mapping` (declared `case-list` structure, alias column matching, conflicts, row-level preview with lineage to source SHA-256, sheet and row; the source is hashed, scanned with `core` `doc_controls` and never written), `quarantine` (staged batches, human approval gate with a different named approver, supersession history, SQL portable to SQL Server) and `export` (CSV and one-way read-only Excel with Read me and History sheets, read-only comparison). `python -m zava_forward.importer preview FILE` prints the preview.
* Failed-import producer (#135, partial, synthetic data only): `exceptions` records a refused file or blocking mapping preview in a durable `import_refusals` table (`submit_file` reads a source once, bounded; one row per content hash of the bytes actually read, first reason kept; refusal reasons are fixed phrases that never copy row, cell or header text). When content identity cannot be established (too large, unreadable, or changed or growing while read) there is no digest and the refusal gets an opaque `source:` identity from the resolved path and file state, or a per-attempt identity when the file cannot be read at all, so same-named files in different directories or a replaced file are never merged; the digest of a later reopen is never attributed to an earlier failure, and an unreadable file resubmitted gets a new record. Identity from file state is not proof of content: a deliberate in-place rewrite that restores size and modified time would reuse it and `route` raises refused files and rejected batches into the core `ExceptionQueue` through `feed_failed_imports` for a configured data steward, keeping the source name, hash (unset for a hashless refusal, whose name carries the opaque identity), reason and `Unknown` eligibility (version and structure stay in the importer for rejected batches only; a refusal has no batch version). With no configured steward nothing is raised and the count is reported as Unassigned (Unknown). `python -m zava_forward.importer stage FILE --db DB --staged-by NAME` stages or records the refusal (exit 1 means a durably recorded refusal; exit 2 means the command or database failed and nothing was recorded); `python -m zava_forward.importer exceptions DB` is a read-only local diagnostic (owner from `ZF_EXCEPTION_STAFF`, not access control). Nothing is replayed, approved, recovered or sent to a model. Fixed file and mapping reasons do not make a rejected batch's note safe: that note is human-entered free text, is not sanitized, and is shown as written. The register and served screen do not read this yet: that needs a store and register hook owned by the shared integration (contract in the #135 RPI details), so the failed-import source in the register stays NOT_CONNECTED. Not run against SQL Server.
* Not built: the HTTP or web surface for import and the export buttons on every list (the api may not import `importer` until #144), the queue transport, the importer image behaviour and limited SQL role, AI-assisted column suggestion with human approval, and the staged transition thresholds, which owners must set (ADR 0001 open item). The upload checks and local scanner that exist today are in the [api](../api/README.md) and [core](../core/README.md) documentation and are labelled synthetic.

Run the suite from `src/importer` with `python3 -m unittest discover -s tests`. The index of projects is [src/README.md](../README.md).
