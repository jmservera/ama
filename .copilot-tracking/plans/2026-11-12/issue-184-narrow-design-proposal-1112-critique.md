# Narrow engineering proposal for the #184 live demo: critique (2026-11-12)

Critique of [the plan](./issue-184-narrow-design-proposal-1112-plan.md) and [research](../../research/2026-11-12/issue-184-narrow-design-proposal-1112-research.md), run before the details were written, so the details and proposal section apply it. Execution: ONE invocation of the read-only `rubber-duck` agent (harness default model, no edits) in the session that authored the plan. It received the plan, the research and a five-point outline of the intended proposal, and it spot-checked the cited source. It is not the coordinator's independent exact-head review and is not repeated. Every finding below was verified by the author against source before disposition.

| # | Severity | Finding | Verification (base `b6f61b12`) | Disposition |
| --- | --- | --- | --- | --- |
| 1 | Significant | A reading id filter does not establish run identity: ids omit the seed, and a same-id different-content row is an identity conflict | `live_readings.py:175` builds the id without a seed; `sensor_consumer.py:998-1003` returns `IDENTITY_CONFLICT` when `(sensor_id, reading_id)` exists | Applied: identity is the pair `(sensor_id, reading_id)` plus run seed on the decoded row, and a read-only pre-run check that no expected id is already retained is a prerequisite |
| 2 | Significant | A receipt can be a rejection, so "receipted" is not "ingested" | `sensor_consumer.py:1003` sets `status="rejected"` with a reason | Applied: completion counts accepted receipts, and replays of an already accepted identical row, separately from rejected ones; rejection is a non-pass |
| 3 | Significant | Unique attempt keys alone do not enforce a run-wide total | Distinct slots or attempt numbers give unlimited unique keys; `live-simulator-job.bicep:65-67` bounds a replica, not the total | Applied: the durable fence is a finite pre-created ticket pool claimed by atomic compare-and-set, exhausted pool fails closed, restart does not refill it |
| 4 | Significant | A per-attempt gate does not test that the home is still in the cohort | `live_simulator.py:474-482` gate tests enabled and expiry only | Applied: per-attempt fresh control reload, fail closed, and membership of the home in the current cohort |
| 5 | Significant | A money limit is an admission limit, not a billed ceiling; actual use can exceed a reservation | `ai_consumption.py:771-785` records `liability-unknown` or an overrun hold after the call | Applied: tokens and money are described as reservation and admission controls with overrun and unknown liability held; no billed-cost ceiling claimed |
| 6 | Significant | End-to-end evidence needs explicit id matching across stages, and a Quality capture can include older rows | `sensor_view.py:300-330` newest-12 plus context; `assistants.py:265-330` flag cites any captured row | Applied: every stage evidence row must name manifest ids; a flag whose sensor-cited ids include no manifest id is not run evidence; the model portion stays unproved while the guard stands |
| 7 | Significant | Future financial authorization could be read as accepting unspecified liabilities | rev2 details section 4 requires owner, duration and teardown; unknown liability is a hold | Applied: the authorization handoff lists those prerequisites and states a named spend authorization does not accept unlisted liabilities |
| 8 | Minor | Research overstates receiver failure ("1000 receipts unreachable, every window exits 2") | `iot_stream.py:268`, `:322` | Applied: research F-findings corrected to "a window with fewer than 1000 accepted-or-replayed receipts ends `RUN_DEADLINE`, exit 2" |
| 9 | Minor | `label` is retained only in the delivery observation body, not the Quality projection | `sensor_consumer.py:28-40` columns exclude `label`; `sensor_view.py:28-36` projection holds `scenario` and `schema_version` but not `seed` | Applied: storage surfaces named. `seed` is in the retained reading row; `scenario` is the only run-tag field visible to the Quality projection, which makes it an owner decision (D1), not assumed |

No finding conflicted with a confirmed owner decision, and none needs an owner decision beyond those the proposal already names. Residual: the author wrote the critique request and the dispositions; the coordinator's independent review of the exact head is still required. No second critique is run.
