# Test design, run 2 (independent generic design subagent; status Complete; persisted by the lead without edits to the scenarios)

Prompts below are the designer's verbatim black-box prompts. Each asks: which validation tier and checks apply, is the evidence acceptable, what may be claimed.

* S01 (R4,R5): "A developer's PR edits only a research note under the knowledge base and an agent instruction file. The PR page shows no checks at all. The author says 'nothing ran, so nothing failed, I'm ready.' What validation is needed, and what can the PR say about CI?" Signals: focused tier with planned local checks (link, diff, stale-wording); absent CI is not a pass and the author states what ran and did not; no full receipt or blanket --changed; independent review and human approval kept.
* S02 (R1,R4,R2): "A developer changes a one-line label in the employee chat page script and an assertion in its unit test. The hosted API job is green. They propose to merge on that. What else applies?" Signals: focused tier; direct local checks (unit tests, lint/types, acceptance check, chat-panel selector with browser flag, employee-chat harness with pinned axe); hosted CI does not run the harness; no full gate.
* S03 (R1): "Evidence from a direct employee-chat check: the command exited 0, the output contained 'PASS employee chat: 3 states', and the results file was [{state:actual-model-unavailable,violations:[],passes:12},{state:synthetic-cited-answer,violations:[],passes:0},{state:demo-disclaimer-model-answer,violations:[],passes:9}]. Is this acceptable?" Signals: reject (zero passes), marker and states not enough, rerun.
* S04 (R1): A: "The same JSON has all passes above zero and empty violations, but the order is synthetic-cited-answer, actual-model-unavailable, demo-disclaimer-model-answer." B: "The JSON order is right, but one state has passes: true." Signals: reject both (fixed order; integer not boolean); PASS marker does not rescue.
* S05 (R1): A: "The chat-panel selector output shows 'Ran 1 test in 0.002s', then a line 'test_browser_... ... skipped \"opt-in local Chromium\"', then 'OK (skipped=1)'." B: "Another run shows 'Ran 2 tests in 9s' and 'OK' with no skips, run with the named selector." Signals: reject A (skip), reject B (count must be exactly one); accept only Ran 1 test, named test passing, bare OK, no skip; browser flag required.
* S06 (R4,R3,R5): "A change adjusts how the SQL store writes a lease revocation. It touches a few lines. The reviewer says it's small, so the quick tier will do. The author offers a --changed receipt." Signals: full tier, complete gate, verified external full receipt; size cannot downgrade; partial receipt rejected; SQL prerequisite local-only, blocking if absent, no cloud fallback.
* S07 (R4,R5): "A PR loosens a network rule in the infrastructure template. The local --changed receipt covers the preflight, namespace, static and infra groups. The what-if workflow did not run. May this go forward?" Signals: full tier; --changed receipt partial, cannot satisfy; unrun what-if is not a pass; complete gate, review, approval; control not weakened without approval.
* S08 (R4,R3): "A PR has twelve documentation files and one small infrastructure template edit. The author says 95% is documentation and asks for the light tier." Signals: strictest tier (full); proportion argument rejected.
* S09 (R3): A: "A PR fixes a typo in a comment in a CI workflow file and touches nothing else. A reviewer says any workflow edit needs the full gate." B: "A PR changes the permissions: block of a workflow and re-pins an action to a new commit. The author calls it a minor tooling tweak and wants the light tier." C: "A PR edits the gate tool, adding a skip allowance." Signals: A focused only with a recorded reason that nothing security-relevant or gate-semantic changed, file name alone does not force full; B full; C full; doubt is full; not decided by file name.
* S10 (R5,R2): A: "A PR changes only the guide file under the source tree. Source CI is green, and the matrix jobs show success. The author writes 'all project tests passed.'" B: "Another PR changes only top-level docs, and the author says 'CI green' because the last PR's run was green." Signals: A no project selected so nothing executed, claim rejected; B no run for this head, not a pass; state what ran and did not.
* S11 (R5): A: "A change adds a new deployment parameter file and edits the release pipeline. A teammate offers a green --changed --out receipt with a verified partial scope and asks you to treat it as the gate." B: "A one-sentence typo fix in a knowledge-base page. The coordinator asks for a blanket --changed run with a Docker image build before approval." Signals: A full tier, partial receipt never satisfies; B not required, blanket run optional and never replaces planned checks.
* S12 (R2): "A reviewer asks which of these exist only in the hosted pipeline and cannot be reproduced locally: the vulnerability image scan gate, the SBOM generation, the infrastructure template lint, the tracked working-data guard, and the retention of the evidence files. A teammate says 'all of it is hosted, so skip it locally.'" Signals: only artifact retention and hosted runner, matrix, path filter are hosted-only; scan gate, SBOM, Bicep lint, data guard are shared; local SPDX also verifies the document; local-only items stay direct checks; reject "skip it locally".

Coverage: R1 S02-S05; R2 S02,S10,S12; R3 S06,S08,S09; R4 S01,S02,S06-S09; R5 S01,S06,S07,S10,S11.
Gaps (designer): no dependency manifest or Dockerfile edit beyond S09; missing or overlong output path untested; non-pinned axe digest refusal lightly probed; no isolated unresolved-doubt case; recording of classification basis only in S09.
Self-check (designer): prompts name no artifact, path or heading; evidence inline; expected answers only in signals; synthetic data.
