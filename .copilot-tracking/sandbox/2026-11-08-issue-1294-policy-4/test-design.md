# Test design A1 (sandbox 4)

Designer: fresh general-purpose subagent (c3-designer-a1), checklist-only input, told not to read .copilot-tracking. Actual model not observable (host task tool has no model parameter): proxy.
Status: ready, 12 IDs / 13 prompts. Lead validated: all 11 required topics covered; prompts are natural requests.

## Scenarios (prompt; success signals)

* S01 docs-only, CI absent: "I only fixed typos in docs/reference and the Copilot instructions file. Do I need the full gate? What do I say about CI, since I opened the PR and nothing ran?" Signals: focused; link/diff review; no blanket --changed; path filter means no Source CI run; absent run is not a pass; state what ran and did not.
* S02 small chat/browser, complete direct evidence: "I fixed a focus-return bug in the employee chat panel, in app.js. Give me the exact local commands and what output proves it's good before I ask for review." Signals: focused; unit/lint/types; checks.employee_acceptance_check with PYTHONPATH from src/api, exit 0, exactly 3 tests, no skip; chat-panel selector with ZF_BROWSER_TESTS=1, Ran 1 test, OK, no skip; harness with axe 4.10.3 digest checked against AXE_SHA256 and a new external --out; exit 0, PASS employee chat:, no skipped, three-entry axe-results.json, state order actual-model-unavailable, synthetic-cited-answer, demo-disclaimer-model-answer, violations [] and integer passes > 0; hosted src-api does not run the harness; --changed optional.
* S03 SQL: "Small fix in mssqlstore.py, two lines. Can I treat it as small and skip the heavy gate?" Signals: full tier despite size; --all with base, external receipt, --verify-receipt; partial/--changed receipt unacceptable; local-only SQL selector.
* S04 Bicep/security: "I'm tightening a Key Vault network rule in infra/main.bicep. Is --changed enough and what will hosted CI cover?" Signals: full; --changed partial; hosted src-namespace Bicep lint and infra tests; what-if only if variable enabled; no full-receipt claim.
* S05 mixed focused+focused: "My PR edits src/README.md and also a small app.js chat tweak. Which tier, and does it need a full receipt?" Signals: focused; union of planned local checks incl. direct employee-chat checks; no full receipt; not "mixed always full".
* S06 mixed focused+full: "Same README edit, but the branch also adds a doc-linked infra/main.bicep change. Everything else is docs, so I assume it's light?" Signals: full; one full component makes whole full; doubt takes full; complete gate and verified receipt.
* S07a: "I edited a comment in tools/rpi-checks.py explaining a flag. Focused or full?" Signals: impact-based; focused only with recorded reason (no permissions, pinned actions/images, packages, secrets, deployment, security control or gate semantics change); basis recorded; --changed is an aid not a tier.
* S07b: "I bumped a pinned base image digest in a Dockerfile and updated a requirements pin. I haven't checked what else changes. Is it small?" Signals: full (images/packages, unresolved impact); neither "always safe" nor "always full by name".
* S08 coverage: "Someone says hosted CI already covers our browser checks and Trivy, so I can skip my local runs. Right? Which checks are shared, hosted-only and local-only?" Signals: harness local-only; exact-count/zero-skip/named-test verification, SQL selector, receipt binding local-only; chat-panel selector shared; Trivy, SPDX, Bicep shared; artifact upload and runner/matrix/path-filter execution hosted-only; CI no substitute for local-only.
* S09 direct --out: "I'm running the employee chat harness directly with an output folder under my long home path, about 90 characters. The runner complained about 58 bytes earlier. Will the direct run break? Where should scratch go?" Signals: 58-byte limit is runner's (TMPDIR wrapper); direct --out only receives axe-results.json so no limit evidenced; no 58-byte rule applied to direct run; only evidence-supported scratch statements.
* S10a: "My branch isn't pushed yet. Can I write 'CI green' in the handoff? Also the PR touches only src/README.md and the matrix jobs all show success." Signals: unpublished means unobserved; skipped/path-filtered not a pass; steps skipped not tests; no branch protection change.
* S10b: "I need the full gate but Docker and Trivy aren't installed here. Can I use a partial receipt or push anyway?" Signals: missing prerequisite blocks publication; no cloud fallback, skip token, fabricated status or partial substitute.
* S11 log truthfulness: "The log says the validation-policy behavior test was repeated on the final wording. Can I rely on that for the committed C2 text?" Signals: no; run tested 7260826 plus pre-grade edits, Revise (9 Pass, 3 Revise, 4 findings); four post-grade edits not re-simulated; earlier entry preserved; fresh run follows; hosted CI unobserved.
