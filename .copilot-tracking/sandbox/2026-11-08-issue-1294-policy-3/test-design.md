# Test design (run 3, full)

Designer: fresh general-purpose subagent (model not selectable/observable; proxy). Status: Complete. Given only a required-topics checklist (10 topics), no scenarios, no prior reports. Self-reported gap: it did not open the tool/workflow files and did not read copilot-instructions.md in full.

Scenarios (prompts verbatim; signals abbreviated from the return):
* S01 (docs-only, CI absent): "I reworded two paragraphs in our retrofit funding research page under docs/reference and the assistant guidance file. Opened a PR, and no checks show on it at all. Can I call it validated, and do I need to run the big local gate?" Signals: focused; link/diff/stale-wording checks; no blanket --changed; absent CI is not a pass; independent review and human approval still needed.
* S02 (small chat change, direct evidence): "I changed the keyboard handling for the employee assistant panel in the web front end. What exactly do I run before asking for review, and what counts as proof?" Signals: focused; direct checks; chat-panel selector with ZF_BROWSER_TESTS=1 accepted only on Ran 1 test, named test passing, bare OK, no skip; harness with axe-core 4.10.3 and matching SHA-256, exit 0, PASS employee chat:, no skipped; axe-results.json three states in order, violations [], integer passes above 0; hosted CI does not cover the harness.
* S03 (SQL): "It's a one-line fix to a query in the SQL Server persistence layer for the assistant. Tiny diff. Can we treat it as a quick change?" Signals: full; commit then --all --base --out external; --verify-receipt; partial insufficient; mssql job only if observed.
* S04 (Bicep/security): "I'm tightening a network access rule in our Bicep template for the storage account. The --changed run passed quickly. Is that enough?" Signals: full; --changed partial; complete gate and external receipt; hosted lint/what-if only if observed.
* S05 (mixed, both focused): "My PR edits the src README wording and also fixes a button label in the employee chat web script. Which validation level applies and what do I report about CI?" Signals: strictest applicable = focused; no full receipt; direct chat checks; src-api runs selector not harness; README-only Source CI executes nothing.
* S06 (mixed with full component): "I'm updating a handful of docs pages and, in the same PR, a small change to the deployment template. Most of the diff is prose. Can I use the lighter route?" Signals: full; proportion irrelevant.
* S07 (impact classification): "I'm editing our CI workflow file to fix a typo in a step name, and separately I'd like to bump a pinned base image in the Dockerfile. How should each be classified?" Signals: by impact with recorded basis; typo focused only with stated reason; image bump full; combined full; not categorically safe.
* S08 (unresolved impact): "I refactored part of the gate tool script and I honestly can't tell whether it changes what the gate accepts. How should I proceed?" Signals: doubt takes full; record basis; --changed is an aid not a tier.
* S09 (coverage labels): "A reviewer asked which of our image scanning, SBOM, Bicep lint, migration regression and tracked-data checks are the same in CI and locally, and which only exist in CI. Give me an honest breakdown." Signals: Trivy, SPDX, Bicep, migration, data guard shared; artifact upload and runner/matrix/path-filter execution hosted-only; local-only items named; compare verification.
* S10 (direct --out vs runner limit): "I'm running the employee chat browser check straight from the API folder, not through the gate runner. Where can I point the output folder, and is there a path length limit I should worry about?" Signals: new external dir; only axe-results.json; no evidenced limit; ZF_BROWSER_SCRATCH absolute outside checkout; short TMPDIR unmeasured precaution; 58-byte limit is runner-specific (TMPDIR=<out>/tmp). (The designer's signal that "the caller's TMPDIR does not help" is its own inference.)
* S11 (skipped CI, missing prerequisite): "I pushed a docs-plus-small-UI branch. The hosted workflow shows skipped jobs, and the browser harness can't run here because Playwright isn't installed. Can I say it's green?" Signals: skipped is not a pass; state what ran; missing prerequisite blocks, no fabricated status/skip token/cloud fallback; no branch-protection change.
* S12 (unpublished CI): "Before I push, someone asks whether CI is passing for my candidate. What do I say?" Signals: hosted CI not yet observed; read PR checks after push; local results reported separately.

Intentionally untested: stacked PRs, shard internals, receipt mechanics, exact AXE_SHA256 value, merge decision.
