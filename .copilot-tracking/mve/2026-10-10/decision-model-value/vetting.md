## Phase 3: Vetting

| Category | Disposition |
| --- | --- |
| Business sense | Pass for the exercise: owner prioritizes value before further build. Application preparation has a measurable effort/quality outcome; company grant or delivery benefits remain unverified. |
| Crisp problem | Pass: compare narrow task replacement and agent complementarity, not model call success. |
| Responsible AI | Conditional: shared permissions/validators, explicit unknowns, blinded labels, immutable inputs and mandatory review. Include contradictory, stale, restricted and unreadable sources. No attributes inferred about real people; source payloads stay private. Report slice differences without claiming demographic fairness from artificial data. |
| Next steps | Pass: retain rules, replace bounded tasks, add hybrid tools, or stop/redesign according to preregistered gates. Owner approves placement; agents cannot activate new operational rules. |

## Red Flags and Mitigations

| Pattern | Status and mitigation |
| --- | --- |
| Demo/prototype | Avoided: live feasibility already exists; deliver comparative findings including negative results. |
| Skipping ahead / mini-MVP | Avoided: freeze unrelated application development during execution; build only adapters, dataset and measurement needed. |
| Solved problem | Unresolved locally: advertised model benchmarks are not retrofit-task comparisons. |
| Low commitment / no next steps | Owner priority and explicit architectural decision provide commitment; no fictional company sponsor is invented. |
| No end users / follow-through capacity | Open risk: no real company staff. Recruit representative human engineers to measure exercise effort; label their experience and limit generalization. Without them, only engineering findings are reportable. |
| Production code expectations | Avoided: isolated evaluation harness; no live state write or production-readiness claim. |
| Show without teach | Owner/second-engineer replay check is planned; no partner-team participation is claimed. |

## Safety and Independence

Blind adjudicators to arm/model identity. Generator oracles are provisional
labels until two human reviewers resolve them; role agents cannot adjudicate.
Keep final reviewers independent of field preparers. Verify zero source edits,
controlled approvals, transmissions and payments in every arm. Evidence
instructions remain data; external text never controls tools or permissions.

Any restricted disclosure, prohibited action, critical unsupported fill or
silent failure stops that task, preserves failure evidence and prevents
activation. All arms run in shadow evaluation outside the live database.

Vetting outcome: viable engineering experiment and conditional human-value
trial. Participant availability is an execution prerequisite, not a reason to
postpone designing the experiment or fabricate measured benefit.
