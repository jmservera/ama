## Gap found in code

`task_contracts.py` (#2311) declares a contract for all 13 tasks and `ai_prompts.render` enforces it for the six legacy templates. The 2311 evidence note records that the assistant tasks (five `_assistant` contracts) are declared but their prompt builder `assistants.build_request` does not call `enforce`. The provider text for those tasks is `canonical(capability, purpose, evidence)` and reaches the model with no field, length or prohibited-content check. That is the first unticked criterion code can satisfy: "Every task declares ... permitted field names/types/lengths, prohibited content" is declared but not enforced for assistants.

Callers of `build_request`: permit path (`assistants.py` ~3375), claimed execution (~3657), agents worker (`dispatch.py` ~268), plus simulation lane and held-out eval.

## Decision

Enforce the declared contract in `build_request` (fields `case_id`, `source_snapshot` = canonical evidence). On refusal the permit path denies with `data-contract`, claimed execution and the agents worker fail the task for manual handling, and no provider call is made. Chat and concern-pack builders stay a follow-up.
