## New angle

`ChatPanel.ask` (src/core chat_panel.py) order of effects: `chat_resume` (read), then under the store lock `chat_add_message(user)` (first commit), later the assistant message and audit. A lock timeout raised before the user message commits leaves nothing stored, so a retry is safe. Any later failure may follow a committed question, so it stays 500. The `finally` audit write can also hit the lock and replace the original exception, which would hide the busy cause.

Existing test `test_busy_sql_write_lock_on_other_post_still_answers_500` patches `chat_resume` on ask and pins 500; the new rule must not break the post-commit pinning, and that test must be reworked to a post-commit failure.

## Plan input

Mark a not-yet-stored turn: `ask` raises `ChatTurnNotStored` (from the busy error) when a lock-busy error occurs before the question is stored, including when the audit write fails. Server treats it as retry-safe 503.
