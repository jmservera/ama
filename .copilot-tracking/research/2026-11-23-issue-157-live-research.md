* New angle (not in the 11-12, 11-18, 11-19, 11-21 records, which cover memory-as-evidence, live probes and docs): case scoping at thread creation. The API route `POST /threads` checks `store.detail(case_id, user)` and returns ChatNotFound, but the core service `ChatPrivacy.start_thread` -> `ChatMixin.chat_create_thread` only checks that the case exists. A caller of the core service (another route, agent or test harness) can therefore create a thread bound to a case the role cannot see (a contractor on another contractor's case), and gets a different error for a missing case (ValueError "Unknown case.") than for a hidden one, an existence oracle. Evidence: src/api/src/zava_forward/api/server.py:1732-1735, src/core/src/zava_forward/core/chat_privacy.py `start_thread`, chatthreads.py `chat_create_thread`; `chat_resume` and `_ask` already fail closed with ChatNotFound on read.
