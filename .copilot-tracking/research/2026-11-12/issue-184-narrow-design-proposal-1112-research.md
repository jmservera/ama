## Findings that shape the proposal

1. The receiver cannot isolate a run today: every window replays the retained stream for the cohort's devices, counts any receipt (accepted, replayed or rejected) toward `max_events`, and discards its tally on a deadline. A window that ends with fewer than `max_events` receipts is `RUN_DEADLINE`, exit 2; whether a small run reaches the default 1000 depends on retained history, which is not a run boundary (consistent with the 2026-11-11 rev2 record, now anchored to current lines). Corrected after the critique (finding 8).
2. Run identity can reuse existing wire fields. `reading_id` already encodes sensor and 5-minute slot but not the seed, so the id alone is not run identity: a same-id row with different content is rejected as `IDENTITY_CONFLICT` (`sensor_consumer.py:998-1003`) and a `Receipt` can be `rejected`. `seed` is a retained reading column settable by the existing `--seed` or `ZF_SIM_SEED`; `label` lives only in the delivery observation body; `scenario` is the only run-tag field also in the Quality projection (`sensor_view.py:28-36`). No schema change is needed to mark a run, but the design needs a manifest of exact expected `(sensor_id, reading_id)` pairs, a seed never used before, a pre-run check that no expected pair is already retained, and a count of accepted (or accepted-replay) receipts only. Added after the critique (findings 1, 2, 9).
3. Retry and replica safety is a counting problem across processes. The repository already has a proven pattern for it in the model meter (insert-before-act, unique attempt, never refund). The transport side has no equivalent, and the simulator identity is documented as read-only to SQL, so a durable fence needs a substrate and a permission decision that this proposal cannot make.
4. The model path has strong existing enforcement of calls, tokens and (given records) money, and it is database durable across replicas. What is missing is not a new meter. It is (a) an explicit statement that byte reservations, not characters or actual tokens, are what is admitted, (b) pinned tests, (c) the unissued authority and price records, and (d) a scanner scope that is not the cohort.
5. The live-model criterion cannot be met in this release while F11 stands. This proposal does not weaken F11. Removing or narrowing it would be a separate privacy, consent and safety design with its own independent review. It is recorded as a named owner decision, not proposed.
