### Diagnosis

`pyproject.toml` marks `zava_forward.api.server` with `follow_imports = "skip"` and `ignore_errors`. When only the test file is named, `server` is not a command-line target, so it is skipped and `App` is typed `Any`, hiding the untyped call. The configured run lists `src`, `tests` and `checks`, so `server.py` is a target, is analysed, and `App.__init__(self, store, password=None, timecap=None, provider=None, law=None)` is an untyped definition. The earlier strict mypy was file-scoped, a proxy that did not cover the configured context. Earlier claims ("mypy strict (new test) exit 0") remain true for that invocation only and are qualified, not erased.

### Prior art

* Other test modules avoid the error through per-module `disallow_untyped_calls` or `ignore_errors` config overrides (excluded here), or `# type: ignore[no-untyped-call]` (`test_case_journey.py:559`, `scale_load.py:102`; excluded here).
* Typed boundary casts exist (`test_resident_chat_api.py:720` `cast(list[Any], ...)`); `Callable[...]` contracts are used in `test_ai_transport_deadline.py`.
* `make_handler(app: App)` is typed, so a factory must return `App`.

### Chosen minimum

In the new test only: a narrow explicit contract `cast(Callable[[Store, str], App], App)` matching the verified constructor call `(store, password)`; no Any, no ignore, no config change.
