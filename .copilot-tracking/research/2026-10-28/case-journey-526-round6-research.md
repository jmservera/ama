## Cycle one

### Wider

Read assistant review/queue/load, generic refresh, draft review, all field
snapshot/capture/cache/restore/recovery helpers, quality actions and checklist
switching. Existing browser harnesses already exercise same-revision restore,
revision isolation, real calls, quality, document review and dispatch-time edits.
Reflection: shared keyed reconciliation is needed, not two local DOM-only fixes.

### Deeper

Dispatch must retain raw value, checked/files identity, semantic key and owning
session. Success retires an equal cached snapshot and equal current counterpart;
different current values stay dirty, even if detached originals remain equal.
Recovered checkboxes display text but retain their original checked value/type.
Reconcile all counterparts, not just the key-deduplicated winner. Recovered
controls must stop claiming already-submitted values; remove emptied recovery
containers without removing unrelated later drafts. Loader-local snapshots can
otherwise resurrect retired data: restore must use the authoritative current
session cache, not stale arrays. Proposal actions also need shared pending state
across replaced same-revision cards, without disabling copyable editors.

### Contrarian

Unconditional cache deletion loses later edits. Comparing only detached fields
misses current edits. Comparing JSON-normalized or trimmed values loses genuine
whitespace edits. Matching by q-i index or proposal ID alone crosses evidence
identities. Disabling editors prevents later editing/copying. Network errors do
not establish invalid Reason or JSON: report status without false aria-invalid.
Retain explicit missing-Reason and JSON parse validation separately, clear stale
field errors on correction/retry, and prevent duplicate review dispatch.
Generic refresh must not swallow a committed-success/reload failure as a field
validation error. Existing native validation and uncertain-commit controls in
resident/challenge forms retain their separate contracts.
