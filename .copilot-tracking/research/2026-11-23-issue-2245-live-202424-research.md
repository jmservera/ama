## Findings

* Earlier runs covered thread-creation 503 (server), the chat meter seeding, the SQL-store override and a live recheck. All left one item open: a live free-form ask failed with HTTP 500 after 30.5 s, and the 2026-11-22 report says the first question showed no answer.
* New angle: the browser. `api()` in `src/api/src/zava_forward/api/web/app.js` calls `res.json()` on every response. For a keyed POST (chat ask is one), a body that is not JSON rethrows the parser's SyntaxError. A Container Apps ingress timeout (HTTP 502/503/504) returns an HTML or plain-text body, so the chat widget would show "Chat unavailable: Unexpected token ..." instead of the plain-language owner and next-action text the code already defines (`GENERIC_CHANGE_ERROR`). No existing test covers this path (`test_app_wide_ux.py` only covers 401 with JSON).
* The server never sends this for its own 500/503 (always JSON), so the gap only appears for proxy-generated failures, which matches a request outlasting the 30 s gateway window.
* Live Azure: no new live call is needed to prove the client path; the proof is a Node harness reproduction with a non-JSON 504. Live criteria stay as in the 2026-11-23 override note (fix not deployed, so "Model calls: 1" stays unproven; Log Analytics denied, so the 2026-11-22 500 cause stays unproven).
