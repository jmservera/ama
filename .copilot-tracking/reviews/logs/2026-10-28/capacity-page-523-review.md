### RV-002 [High]: New refresh retry can silently discard unsaved appointment drafts

* Related scope: P02-T01; preserve unsaved drafts and safe failed-read recovery.
* Evidence: src/api/src/zava_forward/api/web/ops.js:159 adds onclick: route
  when a mutation succeeded but its subsequent capacity read failed.
  src/api/src/zava_forward/api/web/app.js:169-175 only asks about unsaved
  drafts when nextHash differs from displayedHash. Retrying #/capacity keeps
  the hash unchanged. If a read still fails, app.js:201-209 replaces the
  whole workspace with the unavailable screen. The draft capture/restore at
  ops.js:247-265 is never reached on that failure.
* Reproduction boundary: A lightweight Node VM executed the actual extracted
  route() with an unsaved-form document stub, unchanged #/capacity and a
  rejecting capacity read. Result: confirmations=0, appReplaced=true,
  workspaceStatus="Workspace unavailable: We could not load packages. Try
  again." This verifies route control flow, not a browser interaction.
* Impact: After saving one action, a different unsaved appointment form can
  disappear on a repeated read failure without confirmation or recovery.
  The new retry introduces this path; the underlying same-hash route guard
  predates the change. It violates the accepted draft-preservation boundary.
* Destination: Later rpi-implement.
* Smallest useful next action: Keep refresh retry within a read-only recovery
  path that retains drafts across repeated failures, without replaying the
  successful mutation. Add coverage with another unsaved appointment form,
  mutation success, failed refresh, failed retry and eventual successful
  reload; verify saved and unsaved forms separately.
