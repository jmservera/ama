### PC-001 [Critical]: P01-T01 scanner exception and Defender tag coercion breaks existing #395 fail-closed rescan contracts

* Related IDs: P01, P01-T01, P01-T02, P03, P03-T01, C2, C3, C4
* Evidence: src/core/src/zava_forward/core/doc_controls.py (lines 55-182), src/core/src/zava_forward/core/document_rescan.py (lines 80-115), src/core/src/zava_forward/core/store.py (lines 1218-1244), src/core/tests/test_document_rescan.py (lines 165-184, 210-296), src/orchestrator/tests/test_document_rescan_job.py (lines 216-277), .copilot-tracking/details/2026-11-15/issue-117-doc-scan-phase-details.md (P01-T01)
* Concern: `P01-T01` specifies two changes that directly violate existing unit-test invariants in `src/core/tests/test_document_rescan.py` (executed by the mandatory `src/core` unit test suite): (1) changing `DefenderForStorageScanner.scan` so non-empty unrecognized Defender tags (`{DEFENDER_TAG: "Error"}` and `{DEFENDER_TAG: "Not scanned"}`) return `("failed", ...)` instead of `("pending", ...)` breaks `test_actual_defender_tag_reader_outage_and_unknown_stay_pending` (`lines 165-184`), which asserts `result["pending"] == 1` for both tags and then verifies a subsequent `{DEFENDER_TAG: "No threats found"}` sweep transitions the document to `clean == 1`; and (2) catching scanner exceptions and invalid/malformed verdicts inside `scan_new_document` and `_scan_stored` to persist `status="failed"` breaks `test_unknown_and_storage_outage_are_explicit_failures_and_retryable` (`lines 210-226`), `test_malformed_results_fail_closed_without_coercion_and_page_continues` (`lines 228-280`, where `PrivateObject.__str__` also raises `AssertionError` if stringified), and `test_json_and_sql_manual_scan_and_upload_reject_malformed_result` (`lines 282-296`). Those tests require `_scan_result` to raise `RuntimeError` without coercion on malformed shapes or unsupported verdicts such as `"unknown"`, require `scan_new_document`, `rescan_document`, and `rescan_pending` to propagate `RuntimeError` / `OSError` / `TypeError` without mutating case state or appending `document_rescanned` audit entries, and require `document_rescan.run` to catch those exceptions in its outer handler (`report["failed"] += 1`) while rolling back SQL mutations so the document stays `"pending"` and retryable.
* Impact: Implementing `P01-T01` as written causes immediate `src/core` test failures, commits spurious `document_rescanned` audit entries during transient scanner/storage outages, permanently strands transiently errored Defender blobs out of `document_rescan.run` sweeps, and bypasses `Store.add_document`'s exception-driven rollback and blob-deletion path (`store.py:1218-1244`).
* Smallest useful change: Revise `P01-T01` so: (1) `_scan_result` adds `"failed"` as an explicit supported verdict in `("clean", "pending", "infected", "mismatch", "failed")` while still raising `RuntimeError` without stringifying arbitrary objects on malformed return shapes or unsupported verdicts like `"unknown"`; (2) `DefenderForStorageScanner.scan` keeps returning `("pending", ...)` for `{}`, `DocumentStoreError`, and non-clean/non-malicious Defender scan tags (`"Error"`, `"Not scanned"`); and (3) `scan_new_document` and `_scan_stored` raise `RuntimeError("No content scanner is configured; the document remains unavailable.")` when `self.scanner is None` and let scanner/storage exceptions and `_scan_result` `RuntimeError`s propagate unchanged, while recording explicit `("failed", detail)` scanner verdicts and failing closed on any stored `scan={"status": "failed"}` or `scan_status="failed"` record across `scan_status(doc)`, `require_clean(doc)`, and all downstream consumers.
* Action owner: planning_parent
* Exact resolving evidence: Updated `P01-T01` specification in `.copilot-tracking/plans/2026-11-15/issue-117-doc-scan-plan.md` and `.copilot-tracking/details/2026-11-15/issue-117-doc-scan-phase-details.md` preserving `#395` exception propagation and Defender tag retry semantics while supporting explicit `"failed"` verdicts, verified during implementation by `src/core/tests/test_document_rescan.py` passing unchanged.
* Decision route: direct planner correction

### PC-002 [High]: SqlStore drops _scan_stored case persistence when untouched and leaves scan_status unsynchronized outside manual rescan_document

* Related IDs: P01, P01-T01, P01-T02, P03, P03-T01, C3, C4
* Evidence: src/core/src/zava_forward/core/doc_controls.py (lines 174-212), src/core/src/zava_forward/core/store.py (lines 1255-1260, 2140-2145), src/core/src/zava_forward/core/sqlstore.py (lines 1068-1075, 1145-1155), .copilot-tracking/details/2026-11-15/issue-117-doc-scan-phase-details.md (P01-T01)
* Concern: Three persistence/synchronization bugs affect `_scan_stored`, `rescan_pending`, and `rescan_document`: (1) `SqlStore.save()` (`sqlstore.py:1145-1155`) updates `cases` rows in SQLite only for `cid in touched`, and `Store._case(case_id)` (`store.py:2140-2145`) is the only method calling `self._touch(case_id)`. `DocControlsMixin.rescan_pending` (`doc_controls.py:186-198`) iterates `self.cases[cid]["documents"]` without calling `self._case(cid)`, and `_scan_stored` (`doc_controls.py:174-181`) mutates `doc["scan"]` and calls `self.save()` without calling `self._touch(case_id)`. On `SqlStore`, `rescan_pending` commits the `document_rescanned` audit entry while silently dropping the `cases` row update in SQLite, leaving `doc["scan"]` stale on reopen/reload. (2) `P01-T01` synchronizes `doc["scan_status"]` only in `rescan_document`, not inside `_scan_stored`; if a document carries `doc["scan_status"] = "pending"` (or `"failed"`) and is rescanned via `ensure_scanned`, `rescan_pending`, or `document_rescan.run`, `_scan_stored` sets `doc["scan"]["status"] = "clean"` while leaving `doc["scan_status"]` stale, causing `scan_status(doc)` to see a conflict and block the clean document permanently. (3) `rescan_pending` (`doc_controls.py:194`) counts any non-clean status under `out["pending"]` (miscounting explicit `"failed"` verdicts), and `rescan_document` (`doc_controls.py:209`) / `replace_document` (`store.py:1257`) index `d["generated"]` directly instead of `d.get("generated")`, raising `KeyError` when `"generated"` is absent.
* Impact: SQL-backed stores silently lose `rescan_pending` verdict updates across reload/reopen, non-manual rescans wedge records that carry top-level `scan_status` in a permanent conflict state, and legacy upload records omitting `"generated"` raise `KeyError` on manual rescan/replace.
* Smallest useful change: Update `P01-T01` so `_scan_stored` calls `self._touch(case_id)` before mutating `doc["scan"]` and updates `if "scan_status" in doc: doc["scan_status"] = verdict` for all callers (`ensure_scanned`, `rescan_pending`, `document_rescan.run`, and `rescan_document`); use `not d.get("generated")` in `rescan_document` (and `store.replace_document` if touched); avoid counting `"failed"` as `"pending"` in `rescan_pending`; and add a `SqlStore` reopen persistence + `scan_status` sync test in `P03-T01`.
* Action owner: planning_parent
* Exact resolving evidence: Updated `P01-T01` and `P03-T01` specifications in `.copilot-tracking/details/2026-11-15/issue-117-doc-scan-phase-details.md` requiring `self._touch(case_id)` and `scan_status` synchronization in `_scan_stored`, `d.get("generated")` in `rescan_document`, and `SqlStore` reopen rescan test coverage.
* Decision route: direct planner correction
