* Verdict: Revise

### PC-001 [Medium]: Unguarded qualityAcceptanceGap branch in qualityReinspectionState misclassifies Returned defects and contradicts P03-T01

* Related IDs: FR-2, AC-2, P02, P02-T01, P03-T01
* Evidence: `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` lines 211-215 and 274-275; `src/api/src/zava_forward/api/web/role-screens.js` lines 791-795 and 818; `src/api/checks/role_screens_fixtures.py` lines 70-76; `src/api/tests/test_technical_quality_screens.py` lines 294-308.
* Concern: In `src/api/src/zava_forward/api/web/role-screens.js:791-795`, `qualityAcceptanceGap(r)` does not inspect `r.state`; whenever `r.accepted_by` is absent, it returns `"accepted without a named inspector"` (non-empty). In `P02-T01`, `qualityMeasureState(r)` and `qualityCheckState(r, i)` both guard `qualityAcceptanceGap(r)` behind `r.state === "Accepted" || r.state === "Handed over"`, whereas `qualityReinspectionState(r)` specifies `"Action needed: Reinspection lacks independent named inspector"` whenever `qualityAcceptanceGap(r)` is non-empty before falling through to `"Action needed: Not yet possible until fix is recorded"`. Because `Returned` (and `Submitted`) defect records naturally have no `accepted_by` yet (including `technical_quality_data()` in `src/api/checks/role_screens_fixtures.py:75`), `qualityAcceptanceGap(r)` is non-empty on `Returned` records, making `"Action needed: Not yet possible until fix is recorded"` unreachable for normal returned defects.
* Impact: Implementing `qualityReinspectionState(r)` literally as written in `P02-T01` displays the wrong textual state meaning (`"Action needed: Reinspection lacks independent named inspector"`) on open `Returned` defects that are still awaiting a contractor fix, and immediately fails `P03-T01`'s own unit test assertion (`Returned` -> `Action needed: Not yet possible until fix is recorded`).
* Smallest useful change: Update `P02-T01` so `qualityReinspectionState(r)` checks `r.state === "Fixed, awaiting reinspection"` first (`"Pending review: Awaiting independent reinspection"`), then checks `if (r.state === "Accepted" || r.state === "Handed over")` returning `qualityAcceptanceGap(r) ? "Action needed: Reinspection lacks independent named inspector" : "Verified: Independent reinspection passed"`, and returns `"Action needed: Not yet possible until fix is recorded"` otherwise. In `P03-T01`, include both an independently accepted defect record and an accepted/handed-over defect record lacking independent `accepted_by` so both branches are asserted while preserving `test_handed_over_after_fix_keeps_passed_reinspection` (`"Passed"` present, `"Not yet possible"` absent).
* Action owner: Planning parent (`rpi-plan`)
* Exact resolving evidence: Updated `qualityReinspectionState(r)` branch specification in `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` (`P02-T01` and `P03-T01`) scoping `qualityAcceptanceGap(r)` to `r.state === "Accepted" || r.state === "Handed over"`.
* Decision route: Direct planner correction (no user decision required).

### PC-002 [Medium]: Planned readiness and measure-state strings contain Unicode em dashes prohibited by the plain-language content standard

* Related IDs: FR-2, NFR-2, P01-T02, P02-T01, P03-T01
* Evidence: `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` lines 97 and 196; `docs/reference/research/ux/content-standard.md` line 27; `src/api/tests/test_regulatory_a11y_cues.py`; `src/api/tests/test_alert_chat_role_wcag_plain_matrix.py`; `src/api/tests/test_timecapture_copy.py`.
* Concern: `docs/reference/research/ux/content-standard.md:27` requires `"Plain ASCII punctuation, no em dashes, no jargon abbreviations without explanation"`, and `src/api/src/zava_forward/api/web/` currently contains zero `\u2014` characters across all served scripts. `P01-T02` specifies `"Action needed: Technical evidence is incomplete \u2014 design version, source facts, missing references or sign-offs still block readiness."` and `P02-T01` specifies `` `Action needed: ${r.state} \u2014 ${gap}` ``, both embedding Unicode em dashes (`\u2014`), and `P03-T01` notes reminding implementers not to introduce banned words in JS comments (`gate`, `hold`, `provenance`, `trace`, `snapshot`, `envelope` scanned line-by-line by `test_content_standard.py`) omit the ASCII punctuation check.
* Impact: Introducing `\u2014` into `role-screens.js` violates `NFR-2` and `docs/reference/research/ux/content-standard.md:27`, diverging from sibling WCAG/plain-language test suites that explicitly reject `"\u2014"` in rendered strings.
* Smallest useful change: Replace both em dashes in `P01-T02` and `P02-T01` with plain ASCII punctuation (`:` or `;`, for example `"Action needed: Technical evidence is incomplete: design version, source facts, missing references or sign-offs still block readiness."` and `` `Action needed: ${r.state}; ${gap}` ``), note in `P01-T02`/`P02-T01` that JS comments in `role-screens.js` are also scanned by `test_content_standard.py`, and assert `self.assertNotIn("\u2014", ...)` across rendered trees in `P03-T01`.
* Action owner: Planning parent (`rpi-plan`)
* Exact resolving evidence: Plain ASCII copy strings in `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` (`P01-T02` and `P02-T01`) and an explicit `"\u2014"` absence assertion in `P03-T01`.
* Decision route: Direct planner correction (no user decision required).

### PC-003 [Medium]: Browser-check verification command fails Python package resolution and omits Issue 231 selectors in role_screens_browser_check

* Related IDs: NFR-1, AC-5, P03, P03-T01
* Evidence: `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` lines 307-312; `.copilot-tracking/plans/2026-11-15/retrofit-technical-quality-wcag-231-plan.md` line 122; `src/api/checks/specialist_keyboard_browser_check.py` line 15; `src/api/checks/role_screens_browser_check.py` lines 16, 27-88, and 695-745; `src/api/checks/connected_home_browser_check.py` line 21; `src/api/checks/atlas_tensions_browser_check.py` line 14; `.github/workflows/src-ci.yml`.
* Concern: Two defects exist in `P03-T01` step 4 (`cd src/api && PYTHONPATH=../core/tests:../agents/tests python3 checks/<script>.py`). First, all four browser-check modules import `from checks.design_system_browser_check import ...`; running `python3 checks/<script>.py` puts `src/api/checks` rather than `src/api` at `sys.path[0]`, failing immediately with `ModuleNotFoundError: No module named 'checks'` unless invoked via `-m checks.<module>` (matching `.github/workflows/src-ci.yml`). Second, `src/api/checks/role_screens_browser_check.py:695-745` reads `selected = sys.argv[1] if len(sys.argv) > 1 else None`; with no CLI selector, it signs in only as `sam@example.test` (`Resident Liaison Officer`), inspects `#/screens` and `stock-queue`, and exits without ever opening `technical-queue` or `quality-queue`. The Issue #231 negative and positive scenarios (`231`, `231q`, `231p`, `231qp`) only run when passed explicitly as CLI arguments.
* Impact: During `P03-T01`, executing the written browser-check command fails on import, and even if `PYTHONPATH` is patched to include `.`, running `role_screens_browser_check` without `231`, `231q`, `231p`, and `231qp` produces a false-green pass that skips `p.ok[role="status"]`, 320px/390px/1280px reflow, 320px table-region `Tab` reach, and read-only/axe checks on `technical-queue` and `quality-queue`.
* Smallest useful change: Update `plan.md` (Validation Lock) and `phase-details.md` (`P03-T01` step 4) to invoke browser checks from `src/api` as `python3 -m checks.specialist_keyboard_browser_check`, `python3 -m checks.connected_home_browser_check`, `python3 -m checks.atlas_tensions_browser_check`, and `python3 -m checks.role_screens_browser_check` across default plus selectors `231`, `231q`, `231p`, and `231qp` (and `python3 -m checks.browser_check` if verifying full NFR-1 regression locally).
* Action owner: Planning parent (`rpi-plan`)
* Exact resolving evidence: Updated `-m checks.<module>` commands and explicit `231`, `231q`, `231p`, `231qp` selector invocations in `.copilot-tracking/plans/2026-11-15/retrofit-technical-quality-wcag-231-plan.md` and `.copilot-tracking/details/2026-11-15/retrofit-technical-quality-wcag-231-phase-details.md` (`P03-T01`).
* Decision route: Direct planner correction (no user decision required).
