## Verdict

* Verdict: Revise
* Rationale: Five substantive, evidence-backed defects (`1 Critical`, `3 High`, `1 Medium`) would break either runtime fail-closed enforcement or test execution as currently planned. Most critically, wiring `ZF_DIGEST_REQUIRE_RETENTION_LOCK` and `ZF_DIGEST_MIN_RETENTION_DAYS` onto the `ledgerVerify` job in `infra/modules/containerapps.bicep` is a runtime no-op because `ledgerVerify` runs `python -m zava_forward.orchestrator.digest_blob --publish`, a standalone module that never imports `zava_forward.core.ledger_digest_blob` and ignores both environment variables (`PC-001`). In addition, `digestRetention` stays unconditional when `ledgerDigestImmutableStorage == false` while `verify_container_retention_lock` ignores `None`/omitted `immutableStorageWithVersioning` (`PC-002`), `infra/tests/test_bicep_policy.py:evaluate()` lacks `copyIndex` and `false` needed to evaluate `blobContainers` loop properties (`PC-003`), multi-blob/conflicting-source/zero-anchor/reconcile posture rules in `ledger_digest_blob.py` have fail-open gaps (`PC-004`), and `P02-T01` references non-existent `_urlopen_transport` and unverified `sanitize_diagnostic` keys (`PC-005`). Every finding is a direct planner correction within confirmed caller scope; no user response is required.

### PC-001 [Critical]: Scheduled `ledgerVerify` job runs `zava_forward.orchestrator.digest_blob`, which ignores `ZF_DIGEST_REQUIRE_RETENTION_LOCK` and `ZF_DIGEST_MIN_RETENTION_DAYS`

* Related IDs: Caller Objective 2, Caller Objective 3, FR-2, FR-4, Research `C10` and `C13`, `P01-T02`, `P02-T01`, `P03-T01`
* Evidence: `infra/modules/containerapps.bicep:494`, `infra/tests/test_bicep_policy.py:421,1185-1193,1220-1224`, `src/orchestrator/src/zava_forward/orchestrator/digest_blob.py:22-24,58-100,109-235`, `.copilot-tracking/details/2026-11-15/platform-115-blob-immutability-phase-details.md` (`P01-T02`, `P02-T01` Boundaries)
* Concern: `P01-T02` wires `ZF_DIGEST_REQUIRE_RETENTION_LOCK` and `ZF_DIGEST_MIN_RETENTION_DAYS` onto `ledgerVerify` in `infra/modules/containerapps.bicep`, and `P02-T01` explicitly excludes modifying `src/orchestrator/` under the assumption that `orchestrator.digest_blob` delegates to `core.ledger_digest_blob`. * Impact: Because Azure ARM creates `immutabilityPolicies` in `Unlocked` state, runtime fail-closed enforcement in `ledgerVerify` is the sole automated guard preventing a deployed `production` scheduled job from reporting `LEDGER_DIGEST_OK` against an unlocked WORM container. * Smallest useful change: Include `src/orchestrator/src/zava_forward/orchestrator/digest_blob.py` (and `src/orchestrator/tests/`, `mypy`, and `ruff` validation) in `P02` and `P03` (`## Scope and Non-Goals` and `## Test Ownership and Validation Lock`). * Action owner: planner
* Exact resolving evidence: Updated plan and phase details add `src/orchestrator/src/zava_forward/orchestrator/digest_blob.py` and `src/orchestrator/tests/` to scope, phase tasks, and validation commands (`PYTHONPATH=src:tests:../core/src:../core/tests python3 -m unittest discover -s tests -q`, `PYTHONPATH=../core/src python3 -m mypy`, `ruff check`, `ruff format --check`), and specify fail-closed `ZF_DIGEST_REQUIRE_RETENTION_LOCK` / `ZF_DIGEST_MIN_RETENTION_DAYS` enforcement and posture fields in `orchestrator/digest_blob.py`.
* Decision route: Direct planner correction (no divergent user decision required)

### PC-004 [High]: `src/core/ledger_digest_blob.py` posture calculation leaves multi-blob mixed headers, policy-vs-header conflicts, zero-anchor/broken-chain publish, and `reconcile_ledger_digests` underspecified

* Related IDs: Caller Objective 3, FR-3, FR-4, Research `C7`, `C8`, `C10`, `C11`, `C12`, `P02-T01`, `P03-T01`
* Evidence: `src/core/src/zava_forward/core/ledger_digest_blob.py:275-322,499-586,605-817,968-1002`, `src/core/tests/test_ledger_digest_blob.py:82-89,451-490`, `.copilot-tracking/details/2026-11-15/platform-115-blob-immutability-phase-details.md` (`P02-T01`)
* Concern: `P02-T01` leaves four posture-synthesis edge cases ambiguous or fail-open:
  1. Mixed headers across multiple blobs: Neither `publish_ledger_digests` nor `verify_ledger_digests` defines weakest-link aggregation when multiple anchors are written or read (for example, `digest-0000000004.json` has `unlocked`, missing, expired, or 30-day headers while `year-2025.json` has `locked` 365-day headers). A last-blob-wins assignment would record `immutability_policy_state="Locked"` and `locked=True`, and uploading remaining anchors after a first unlocked `PUT` would leak writes into an unlocked container before failing.
  2. Conflict between supplied `retention_policy` and blob WORM headers (and missing `x-ms-creation-time`): When both `retention_policy` (for example `365` days, `"Locked"` or `"Unlocked"`) and blob headers (for example `_FakeImmutableBlobTransport` returning `until` 731 days ahead without `x-ms-creation-time`, or `"unlocked"` headers alongside a `"Locked"` policy dict) are present, `P02-T01` does not specify how conflicts resolve. If one source says `"Locked"` and the other says `"Unlocked"` or `"Absent"`, reporting `locked=True` is false; if `x-ms-creation-time` is absent while `retention_policy` supplies `365`, reporting remaining days (`731`) instead of configured `365` distorts `retention_days`. Conversely, in `verify_ledger_digests`, an unrelated ledger hash-chain mismatch (`check == "chain"`) makes `report["intact"]` `False` (`line 743`) and must not flip `report["locked"]` to `False` when the container retention lock itself is valid and `"Locked"`.
  3. Zero-anchor and broken-chain publish paths: With default `head_digests=None`, `publish_ledger_digests([], blob)` actually uploads `digest-0000000000.json` (`count=0, head=GENESIS`, `lines 521-530`), whereas `head_digests=[], sealed_year_digests=[]` uploads zero blobs even when `entries` is non-empty, and broken local chains (`lines 515-519, 574-575`) return `[]` before upload. Keying fallback posture to `if entries is empty` rather than `not anchor_evals`, or returning early on a broken chain before validating supplied `retention_policy` and populating `blob.last_immutability_posture` / `posture_out`, leaves stale/empty posture or skips fail-closed container checks. Also preserve `*` immediately after `blob` in `publish_ledger_digests(entries, blob, *, ...)` (`line 501`) rather than turning `before_year` positional as phrased in `P02-T01`.
  4. `reconcile_ledger_digests` and `_run_reconcile_cli` parity: `FR-4` requires canonical posture checking/recording in `reconcile_ledger_digests`, but `P02-T01` omits adding `min_retention_days`, `retention_policy`, `container_properties`, `lifecycle_prefixes`, and `immutability_policy_state`, `retention_days`, `locked`, `immutability_posture` return fields to `reconcile_ledger_digests` (`lines 756-817`), and omits `_parse_min_days_env(cfg)` in `_run_reconcile_cli` (`lines 968-1002`).
* Impact: Without explicit weakest-link rules, pre-return posture recording, dual-source conflict resolution, and reconcile parity, publisher/verifier posture metadata can report `locked=True` on partially unlocked or conflicting inputs, report wrong `retention_days` in existing multi-year tests, or omit required posture fields on early-return and reconcile paths.
* Smallest useful change: Specify deterministic posture synthesis in `P02-T01` (and cover in `P03-T01`): (a) weakest-link multi-blob aggregation where `locked=True` and `immutability_policy_state="Locked"` hold only when every inspected source (`retention_policy` if supplied and all inspected blob headers, with at least one source present) is locked and has zero retention/container problems, checking each anchor immediately during `publish_ledger_digests` so the first unlocked/non-compliant `PUT` or `409`/`412` `GET` records posture and raises `LedgerDigestBlobError` immediately when `require_retention_lock=True` (falling back to one `read_anchor_with_headers` `GET` if a `200`/`201` `PUT` omits `x-ms-immutability-policy-mode`); (b) when both `retention_policy` and blob headers exist, both must be locked for `locked=True`, any non-locked state (`"Absent"`, `"Unlocked"`, or raw invalid state) wins over `"Locked"`, and `retention_days` uses `min` across valid `retention_policy` days and `x-ms-creation-time`-bounded blob windows (falling back to remaining whole days `(until_dt - ref_time) // timedelta(days=1)` only when neither `retention_policy` nor `x-ms-creation-time` is present); (c) keep `publish_ledger_digests(entries, blob, *, ...)` keyword-only signature, run pre-upload container policy check before broken-chain early return, always write `blob.last_immutability_posture` and `posture_out` on broken-chain and zero-anchor (`not anchor_evals`) paths, and fail closed when `require_retention_lock=True` and `not posture["locked"]` (except broken local chain with no failing policy check still never uploads, or fails closed if `require_retention_lock=True` and policy/lock is unverified); and (d) extend `reconcile_ledger_digests` and `_run_reconcile_cli` with `min_retention_days` / optional container policy args and canonical posture return fields.
* Action owner: planner
* Exact resolving evidence: `P02-T01` and `P03-T01` document the exact weakest-link multi-blob and policy-vs-header conflict rules, zero-anchor (`not anchor_evals`) and broken-chain posture recording, preserved keyword-only signature on `publish_ledger_digests`, and `reconcile_ledger_digests` / `_run_reconcile_cli` posture + `min_retention_days` support, with unit assertions covering mixed headers, policy-vs-header conflict, and zero-anchor fail-closed publish.
