### PC-001 [High]: `FR-S2` / `P01-T01` uses invalid JMESPath `tolower()` in `infra/README.md` and case-fragile ARM/secret scope matching in `_classify_arm_kv_scope`

* Related IDs: `FR-S2`, `SE-2`, `P01-T01`, `P02-T01`
* Evidence: .copilot-tracking/plans/2026-11-15/kv-secret-lifecycle-142-seal-plan.md (`FR-S2`); .copilot-tracking/details/2026-11-15/kv-secret-lifecycle-142-seal-phase-details.md (`P01-T01` item 2); src/core/src/zava_forward/core/secret_lifecycle.py (`default_expected_caller_policy`, `_secret_allowed`, `audit_keyvault_data_plane_access`); src/core/tests/test_secret_lifecycle.py (line 397); infra/role-assignments.json.
* Concern: First, `FR-S2` and `P01-T01` specify `az role assignment list --all --include-inherited --query "[?starts_with(tolower(scope), tolower('<vault-id>')) || starts_with(tolower('<vault-id>'), tolower(scope))]" -o json`, but standard JMESPath in Azure CLI has no `tolower()` function (`UnknownFunctionError` at runtime), and unanchored `starts_with` without `/` segment boundaries over-matches sibling vault or resource-group prefixes (`kv-ama-2` vs `kv-ama`, `resourceGroups/am` vs `resourceGroups/ama`). Second, `_classify_arm_kv_scope` in `P01-T01` checks `/providers/microsoft.keyvault/vaults/<vault>` with `<vault> == vault_name.lower()` and returns `"secret:<secret_exact>"`: literal lowercase provider matching rejects mixed-case `/providers/Microsoft.KeyVault/vaults/...` used in ARM and existing tests, `<vault>` is not lowercased before comparing to `vault_name.lower()`, sibling ARM resources (`/subscriptions/.../providers/Microsoft.Storage/...`) would be misclassified as `"broader_parent"` unless parent scopes are restricted to true ARM ancestors (`/`, management group, subscription, resource group), Key Vault secret names are case-insensitive in Azure (`Entra-Token-Store-Sas` accesses `entra-token-store-sas`) so exact-case `"secret:<secret_exact>"` causes false positives or case-mismatch drift unless secret tokens are normalized with `.lower()` across `allowedRoleScopes`, `_classify_arm_kv_scope`, and `_secret_allowed`, and `default_expected_caller_policy` does not fail closed when a `keyvault` row in `role_matrix` has an unmapped `roleId`.
* Impact: Operators running the documented `infra/README.md` RBAC export command hit an immediate Azure CLI JMESPath error; mixed-case ARM vault/provider/secret scopes fail `audit_keyvault_data_plane_access` falsely or misclassify sibling resource scopes.
* Smallest useful change: Replace the invalid JMESPath `--query "...tolower..."` command in `FR-S2`, `P01-T01`, and `infra/README.md` with a valid case-insensitive `/` segment-boundary filter (`az role assignment list --all -o json | python3 -c 'import json,sys; vid=sys.argv[1].rstrip("/").lower(); print(json.dumps([r for r in json.load(sys.stdin) if (s:=str(r.get("scope","")).rstrip("/").lower()) and (s=="//"[:1] or s==vid or s.startswith(vid+"/") or vid.startswith(s+"/"))]))' "<vault-id>" > roles.json`); specify in `P01-T01` that `_classify_arm_kv_scope` matches ARM resource prefixes case-insensitively (`re.IGNORECASE`), compares `<vault>.lower() == vault_name.lower()`, normalizes secret names to lowercase (`f"secret:{secret.lower()}"`) consistently across `default_expected_caller_policy` (`allowedRoleScopes` and `allowedSecrets`), `_classify_arm_kv_scope`, and `_secret_allowed` (while preserving raw names in `callerSummaries[*].secrets`), classifies only `/`, management-group, subscription, and resource-group scopes as `"broader_parent"` (treating `/providers/<non-kv>...` as `"wrong_vault"` and using anomaly kind `wrong_vault_rbac_scope` or `excess_rbac_privilege` consistently rather than `wrong_vault_diagnostic` on RBAC rows), and fails closed with `SecretLifecycleError` on unmapped `roleId` in `default_expected_caller_policy`; add a mixed-case ARM/secret scope test in `P02-T01`.
* Action owner: planning_parent
* Exact resolving evidence: Updated `FR-S2`, `P01-T01`, and `P02-T01` in `.copilot-tracking/plans/2026-11-15/kv-secret-lifecycle-142-seal-plan.md` and `.copilot-tracking/details/2026-11-15/kv-secret-lifecycle-142-seal-phase-details.md` removing `tolower(...)` JMESPath and specifying case-insensitive ARM/vault/secret normalization and ancestor-only `"broader_parent"` matching.

### PC-002 [High]: `FR-S3` / `P01-T01` breaks chained pre-deadline reviews and `future_audit` fixture in existing core tests, relaxes strict `reviewedAt` monotonicity, and omits `"overdue"` return field / `review_status` parity

Preserve strict `reviewed_at > prev_reviewed_at` in both functions, return `"overdue": overdue` (`False` when empty) from `verify_access_review_ledger` while keeping the overdue `problems` entry, apply `now.astimezone(dt.UTC).date() > dt.date.fromisoformat(str(due).strip())` in `review_status`, and include updating `days=30` to `days=90` at `src/core/tests/test_secret_lifecycle.py:797` in `P02-T01`.

### PC-003 [High]: `FR-S1` / `P01-T01` weakens HMAC key floor to 16 bytes with undefined key helpers, leaves `rollbackVerified` and `containerApp` URI / `hmac.compare_digest` gaps, and omits Entra `enabled: false` rejection

* Evidence: .copilot-tracking/plans/2026-11-15/kv-secret-lifecycle-142-seal-plan.md (`FR-S1`); .copilot-tracking/details/2026-11-15/kv-secret-lifecycle-142-seal-phase-details.md (`P01-T01` item 1); src/core/src/zava_forward/core/secret_lifecycle.py (lines 404-465, 530-605, 641-707, 848-854); infra/scripts/secret_lifecycle.py (lines 147-172, 298-311).

Second, in `verify_staged_entra_rotation` (`secret_lifecycle.py:683-689`), `rollback_verified` does not check that zero `problems` occurred prior to appending `"forward rotation aborted; rollback hold active"`, and probe checking uses `browser_mode = raw_browser_mode`; consequently, in `stage == "rollback"` with `"browserMode": false` and `require_browser_mode=True` (or with invalid `vaultName`, `containerApp.secrets`, or non-bool `enabled`), `rollback_probes_ok` skips `/sign-in` and authenticated probes and still returns `rollbackVerified: True`. ### PC-004 [Medium]: `FR-S4` / `P01-T01` `az ad app credential reset ... -o tsv | az keyvault secret set --value @-` pipeline risks storing a trailing newline in `entra-client-secret`

* Related IDs: `FR-S4`, `SE-4`, `P01-T01`
* Evidence: .copilot-tracking/plans/2026-11-15/kv-secret-lifecycle-142-seal-plan.md (`FR-S4`); .copilot-tracking/details/2026-11-15/kv-secret-lifecycle-142-seal-phase-details.md (`P01-T01` item 4); infra/README.md (lines 1518-1536).
* Concern: `az ad app credential reset ... --query password -o tsv` terminates stdout with `\n` (`\r\n` on Windows/WSL bridges). Piping that stream directly into `az keyvault secret set` stdin without stripping line endings (and relying on `--value @-` rather than newline-stripped stdin / `--file /dev/stdin`) risks writing a trailing-newline secret into Key Vault, causing Container Apps built-in Entra authentication to fail live OAuth token exchange (`AADSTS7000215`), and `infra/README.md` only mentions `--signing-key-env` without documenting `--signing-key-file` (`chmod 0600` outside-repo key file, consistent with `review-sign`).
* Impact: Operators following step 1 verbatim during a live rotation can store a trailing-newline secret version in Key Vault that fails step 2's live token-exchange probe.
* Smallest useful change: Update `FR-S4` and `P01-T01` so the `infra/README.md` step 1 pipeline strips trailing CR/LF before writing to Key Vault (`az ad app credential reset --id <app-id> --append --display-name container-apps-auth-YYYY-MM --end-date <iso> --query password -o tsv | tr -d '\r\n' | az keyvault secret set --vault-name <vault> --name entra-client-secret --expires <iso> --file /dev/stdin --output none`) and step 2/3 documents `--signing-key-file` (`0600`, outside the repository) alongside `--signing-key-env`. Leave `rotation_plan()` step strings compatible with existing `NoDowntimeRotationTests` assertions (`--append`, `new version of entra-client-secret`, `refresh`, `confirm /app`, `credential delete`).
* Action owner: planning_parent
* Exact resolving evidence: Updated `FR-S4` and `P01-T01` in `.copilot-tracking/plans/2026-11-15/kv-secret-lifecycle-142-seal-plan.md` and `.copilot-tracking/details/2026-11-15/kv-secret-lifecycle-142-seal-phase-details.md` incorporating `tr -d '\r\n'` in the stdout-free pipeline and documenting `--signing-key-file` alongside `--signing-key-env`.
* Decision route: direct planner correction
