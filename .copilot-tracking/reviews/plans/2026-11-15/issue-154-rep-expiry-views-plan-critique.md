### PC-001 [High]: ResidentDemo SessionCodec handle collision, shared callback Agenda owner key, and breaking /demo/session contract across residents and representatives

* Related IDs: FR-REP-01, FR-REP-03, NFR-REP-01, AC3, AC4, P01-T03, P02-T01, P03-T02
* Evidence: src/core/src/zava_forward/core/resident_showcase.py:409-424; src/api/src/zava_forward/api/resident_demo/app.py:131,158-186,258-275,346-357,462,555; .copilot-tracking/details/2026-11-15/issue-154-rep-expiry-views-phase-details.md (P02-T01)
* Concern: First, `P02-T01` assumes `__Host-zfdemo` carries `(case_id, canonical_email)`, whereas `SessionCodec.issue(case_id)` hashes only its single string argument (`codec.handle(case_id)`) and `ResidentDemo.by_handle` maps `handle -> case_id`. Issuing `codec.issue(case_id)` for a representative produces the exact same HMAC handle as the household resident on that case and across multiple representatives on the same case, letting `row_for(token)` resolve a representative cookie as the household resident (exposing `home` and `sensors`) or collapsing distinct representatives into one principal (`FR-045` violation). Second, `POST /demo/agenda` (`app.py:555`) scopes callbacks by `owner = resident_key(case_id)`; without a representative-specific owner key, a representative with `Communicate` or `Attend` can list and cancel the household resident's or another representative's callbacks. Third, `P02-T01` specifies `/demo/session` returning `{"authenticated": True/False, ...}` instead of preserving `csrf`, `signed_in`, `session_id`, and `banner` (`app.py:350-356`), which breaks `_csrf_ok()` (`X-CSRF-Token`) and `_session_bound()` (`X-Resident-Session`, `app.py:258-275`, returning `409` before `/demo/view`, `/demo/assistant`, `/demo/agenda`, or `/demo/logout` can return the planned `403` `expired`/`held` transition).
* Impact: Privilege escalation and household/cross-representative disclosure on shared cases in `ResidentDemo`, plus broken CSRF and `409` vs `403` mid-session expiry handling.
* Smallest useful change: Specify in `P01-T03` and `P02-T01` that (1) representative tokens call `codec.issue(...)` with a distinct principal subject (for example `f"rep:{grant.case_id}:{grant.representative_ref}"` or canonical email) stored in a separate `rep_by_handle` lookup disjoint from `self.by_handle`; (2) `/demo/agenda` keys representative callbacks by `resident_key(f"rep:{grant.case_id}:{grant.representative_ref}")` rather than `resident_key(case_id)`; and (3) `GET /demo/session` keeps `csrf`, `signed_in` (`True` when active, `False` when expired/held), `session_id` (preserving cookie token verification in `_session_bound()` while authority is expired/held so `/demo/view`, `/demo/assistant`, `/demo/agenda`, and `/demo/logout` execute cleanly without `409`), and `banner`, adding `viewer_kind`, `state`, `reason`, `expires_at`, and `renewal_route` additively. Add a same-case resident + two-representative isolation assertion to `P03-T02`.
* Action owner: planning_parent
* Exact resolving evidence: Updated `P01-T03`, `P02-T01`, and `P03-T02` sections in .copilot-tracking/details/2026-11-15/issue-154-rep-expiry-views-phase-details.md specifying disjoint codec handle subjects, representative-scoped `Agenda` owner keys, and additive `/demo/session` + `_session_bound()` behavior.
* Decision route: direct_planner_correction

### PC-002 [High]: Authority evaluation contradicts resident_decisions.py on review_date-only grants, versions[-1] precedence, and naive controls.now() clock values

* Related IDs: FR-REP-02, FR-REP-03, AC2, AC3, P01-T01, P01-T02, P03-T01
* Evidence: src/core/src/zava_forward/core/resident_decisions.py:984-997,1039-1041,1645-1672; src/core/src/zava_forward/core/controls.py:17-22; src/core/tests/test_resident_decisions.py:2403-2445; .copilot-tracking/plans/2026-11-15/issue-154-rep-expiry-views-plan.md (FR-REP-02, FR-REP-03); .copilot-tracking/details/2026-11-15/issue-154-rep-expiry-views-phase-details.md (P01-T01, P01-T02)
* Concern: Three domain rules conflict across `P01-T01` and `P01-T02`. First, `FR-REP-02` and `P01-T01` (`effective_authority_expiry`) treat `expires_at` as optional on domain records and derive `review_dateT00:00:00Z` when only `review_date` is present, whereas `FR-REP-03` and `P01-T01` (`evaluate_representative_authority`) state that missing `expires_at` transitions the session/view to `state="held"` (`reason="missing_expiry"`), which would hold every backwards-compatible `_res_representative_record` record created without `expires_at`. Second, `P01-T01` evaluates the "latest version per measure" in `case["representative_authorities"][ref]`, whereas `authority_for()` (`resident_decisions.py:986-988`) and `_resident_decision_gate()` (`resident_decisions.py:1039-1041`, pinned by `test_resident_decisions.py:2427`) evaluate only `versions[-1]` (the single latest record for `ref` on the case); evaluating per-measure in `project_representative_view` would show an earlier measure grant as active even after a newer record superseded or revoked `ref`'s authority in `authority_for()`. Third, `P01-T02` defaults `now` in `authority_for` to `k.now()` or `datetime.now(UTC)`, but `controls.now()` (`controls.py:21`) returns a naive minute-truncated local string (`datetime.now().isoformat(timespec="minutes")`) with no UTC offset, which `parse_iso_utc` rejects as `None` (failing closed on every default call).
* Impact: Backwards-compatible `review_date`-only domain grants fail as `held`, `authority_for` fails closed when defaulting to naive `controls.now()`, and `project_representative_view` disagrees with `authority_for` / `resident_gate` when multiple versions exist under one `representative_ref`.
* Smallest useful change: Update `FR-REP-02`, `FR-REP-03`, `P01-T01`, and `P01-T02` so that: (1) `missing_expiry` (`state="held"`) triggers when no valid effective expiry ceiling can be parsed (e.g., `RepresentativeShowcaseGrant(expires_at=None)`, an explicit null/malformed `expires_at` key on a record, or missing/invalid `review_date` when `expires_at` is omitted), while valid legacy domain records with `review_date` resolve `effective_expiry = review_dateT00:00:00Z`; (2) `evaluate_representative_authority` aligns with `resident_decisions.py` version semantics (using `versions[-1]` for single-stream `representative_authorities[ref]` records, or explicitly documenting only active non-superseded bindings consistent with `authority_for`); and (3) `authority_for(..., now=None)` uses `datetime.now(UTC)` (never naive `controls.now()`) for `expires_at` comparison while continuing to use `k.today()` (or `now_utc.date().isoformat()` when `now` is explicitly passed) so `controls.today` patches in `test_resident_decisions.py:2431` keep passing.
* Action owner: planning_parent
* Exact resolving evidence: Updated `FR-REP-02`/`FR-REP-03` in .copilot-tracking/plans/2026-11-15/issue-154-rep-expiry-views-plan.md and `P01-T01`/`P01-T02` in .copilot-tracking/details/2026-11-15/issue-154-rep-expiry-views-phase-details.md resolving `missing_expiry` vs `review_date`, matching `versions[-1]` precedence with `authority_for`, and using `datetime.now(UTC)` + `k.today()`.
* Decision route: direct_planner_correction

### PC-004 [Medium]: Attend appointment projection and confirm_appointment check in P01-T01 mismatch appointments.py work-order bindings, three-confirmation status, and appointment_authorities schema
