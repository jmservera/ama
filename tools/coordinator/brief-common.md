Common rules for every AMA RPI worker brief (rebuilt 2026-11-20 after a reboot cleared /tmp).

1. Run the full RPI loop in order: research, critique, plan, implement, review. Write dated artifacts under `.copilot-tracking/` (research, plans and details, changes, reviews, rpi-sessions state) in your own worktree. Read `.github/copilot-instructions.md` and obey it.
2. Phase witness: the coordinator already recorded the launch. You call, from the checkout root `/home/azureuser/source/ama`, with the helper `python3 tools/rpi_phase_witness.py record <boundary> --repo <your worktree> --issue <N> --evidence-dir <evidence dir> --state <state file> --session rpi-<N>-live --actor worker --claim-model claude-sonnet-5.5`. Boundaries in order: `research-open` (after persisting the opening state and before substantive search), `plan-done`, `implement-start` (changes record persisted before any source edit), `implement-done`, `review-done`, and `commit-complete --claim-commit <sha>` only after the commit exists. Persist the dated artifact first, then call the witness; it observes the artifact named by `--state`. A refusal is a blocker to fix, never to bypass.
3. Never push, open or update a PR, merge, or change the target. End with one clean frozen local commit (no dirty files). Never stage `__pycache__`, `.mypy_cache` or `.ruff_cache`. Use the Conventional Commit format with `Refs #<N>` and these trailers: `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>` and `Copilot-Session: 8671d16a-64f1-496e-bd03-18d1936ae585`. Set repo-local `git config --local user.email 8036360+jmservera@users.noreply.github.com` in your worktree.
4. Execution hygiene: run the `src/core` and `src/api` test suites sequentially, never concurrently in one worktree; cap every `read_bash` delay at 600 seconds or less; never run `rpi-checks.py --all` (the coordinator runs gates); if you need a gate lock check `/tmp/ama-rpi-heavy.lock` or pass `--lock-timeout 0`.
5. Secrets: never read, print or echo `~/.ama-test-user*` or `~/.ama-resident-test-user` except as a runtime input to a tool; never print tokens or keys.
6. Prove or disprove each unticked acceptance criterion with recorded evidence; do not state unproven items as proven. End with a per-criterion proven/unproven table in the changes record.
